## 3. 岗位页面结论

普通用户侧不使用“岗位管理”命名。

普通用户侧岗位相关页面分为：

- `岗位库`：系统预置岗位，只读参考。
- `目标岗位`：用户自己的目标 JD，可新增、解析、删除。
- `匹配分析`：基于目标岗位和简历生成 AI 匹配结果。

管理员侧如后续新增，才使用“岗位管理”命名。

## 4. 主流程页面与主操作

| 流程顺序 | 页面 | 当前路由 | 主操作 | 主要跳转 |
|---|---|---|---|---|
| 1 | 工作台 | `/` | 上传简历 / 新增目标岗位 / 开始匹配分析 | `/resumes`、`/job-descriptions/new`、`/ai-job-matches` |
| 2 | 我的简历 | `/resumes` | 上传新简历 / 开始解析 / 生成简历诊断 | `/job-descriptions` |
| 3 | 目标岗位 | `/job-descriptions` | 新增目标岗位 / 查看目标岗位 / 开始匹配分析 | `/job-descriptions/new`、`/job-descriptions/:id`、`/ai-job-matches` |
| 4 | 新增目标岗位 | `/job-descriptions/new` | 提交目标岗位 JD | `/job-descriptions/:id` |
| 5 | 目标岗位详情 | `/job-descriptions/:id` | 解析目标岗位 / 开始匹配分析 | `/ai-job-matches` |
| 6 | 匹配分析 | `/ai-job-matches` | 开始匹配分析 / 生成岗位优化建议 / 局部改写 | `/history` |
| 7 | AI 结果回看 | `/history` | 查看历史详情 / 回到业务页面 | `/resumes`、`/job-descriptions`、`/ai-job-matches` |

说明：

- `岗位库` 是辅助参考入口，不作为主流程必经节点。
- `岗位详情` 是详情页，不放入主流程导航。
- `登录` 和 `注册` 是认证入口，不属于登录后的业务主流程。
- 当前 `匹配分析` 页面同时承载岗位优化建议和局部改写，后续可以先通过页面分区和按钮文案降低理解成本。

## 5. 主流程结论

页面主流程按“工作台 -> 我的简历 -> 目标岗位 -> 匹配与优化 -> AI 结果回看”组织。

每个页面只保留一个最主要的下一步动作，详情页和表单页从流程按钮进入，不强行放入主导航。

## 8. v2.9.12 简历解析结果收敛说明

`/resumes` 继续承载“我的简历”、简历解析结果和简历诊断，不新增独立解析结果路由。

解析结果区块调整为：

| 区块 | 展示内容 | 说明 |
|---|---|---|
| 解析状态 | 解析状态、文本质量、结构质量、质量分数、AI 辅助解析状态、AI 降级状态、更新时间 | 让用户先判断本次解析是否可继续使用 |
| 质量提示 | 文本质量提示、解析质量提示、质量警告标签、结构化 `qualityWarnings` | 提醒用户哪些字段可能不完整 |
| 基础字段 | 姓名、手机号、邮箱、性别、年龄、所在地、工作年限、求职意向、最高学历、简历类型 | 空字段显示空状态，不自动补全 |
| 技能关键词 | 技能列表 | 空字段提示暂无技能关键词 |
| 经历分区 | 教育经历、工作经历、项目经历、实习经历、校园经历、获奖经历、证书、自我评价、其他内容 | 按结构化字段分区展示，无法归类但有价值的内容进入其他内容 |
| 其他内容 | 少量未归类但有价值内容 | 默认限制展示数量，避免再次铺满页面 |
| 调试信息 | 原始提取文本、清洗后文本、文本块、章节识别、AI 分类结果 | 默认折叠，便于排查，不作为用户默认主视图 |

解析质量提示补充：

- 未识别姓名时，前端展示 `NAME_MISSING` 对应提示。
- 手机号或邮箱不完整时，前端展示 `CONTACT_MISSING` 对应提示。
- 未识别教育经历时，前端展示 `EDUCATION_MISSING` 对应提示。
- 简历类型未明确识别时，前端展示 `RESUME_TYPE_UNKNOWN` 对应提示。
- 有工作经验简历缺少工作经历时，前端展示 `WORK_EXPERIENCE_MISSING` 对应提示。
- 校招或实习简历缺少实习 / 校园经历时，前端展示 `CAMPUS_OR_INTERNSHIP_MISSING` 对应提示。
- 未识别工作经历、实习经历或项目经历时，前端展示 `EXPERIENCE_OR_PROJECT_MISSING` 对应提示。
- 未归类内容较多时，前端展示 `OTHERS_TOO_MANY` 对应提示。
- 重复内容较多时，前端展示 `DUPLICATE_CONTENT_TOO_MANY` 对应提示。

用户手动修正方案：

- 当前版本只展示解析结果，不实现编辑保存。
- `确认解析结果` 当前仅做前端状态，作为后续持久化确认结果的入口占位。
- `重新解析` 继续复用已有解析接口，不新增接口路径。
- 解析入口不提供 AI 开关，每次解析默认使用 AI 辅助解析；AI 调用失败时自动降级为规则解析。
- 后续如实现修正，应优先在 `/resumes` 的解析结果区提供“进入修正”动作。
- 修正内容建议单独保存为用户确认后的解析结果，不覆盖原始提取文本。
- 修正字段建议覆盖 `basicInfo`、`education`、`skills`、`workExperiences`、`internships`、`projects`、`campusExperiences`、`awards`、`certificates`、`summary` 和 `others`。
- 修正后应重新生成结构化结果质量状态，并提示用户需要重新生成依赖解析结果的 AI 诊断、匹配分析、优化建议和向量数据。
- 本版本不新增修正接口、不新增修正表、不修改后端接口路径。
