# Phase 5 - 产品化优化、部署上线与项目包装阶段

## 当前状态

Phase 1 到 Phase 4 已完成后，项目已经具备从基础 MVP、工程化增强、AI 能力深化到微服务与企业部署的完整技术演进路径。

Phase 5 不再以继续堆叠新技术为主，而是将项目从“功能完整的开发项目”进一步打磨为“可展示、可上线、可讲解、接近真实产品体验的作品”。

Phase 4 收口后已允许进入 Phase 5：主业务流程、文件存储抽象、异步任务模型、安全清单、部署文档、运维文档和主要遗留问题记录均已完成。该结论只表示可以进入产品化优化、正式部署和项目包装阶段，不表示已经完成正式服务器上线。

不阻塞 Phase 5 但需要在正式部署任务中继续处理的事项包括：真实服务器部署、`nginx -t`、后端 / 前端应用 Dockerfile、systemd、HTTPS、MinIO 正式接入、Redis 实际接入、文件日志和 CORS 配置化。

Phase 5 第一批建议任务：产品体验复盘、UI / UX 整理、README 和截图包装、正式部署、域名 HTTPS、备份脚本、简历项目描述和面试讲解稿。

本阶段建议从：

```text
v3.1 - 产品体验复盘与优化清单
```

开始推进。

## 1. 阶段目标

Phase 5 的目标是对项目进行产品化、视觉化、部署化和展示化收尾。

本阶段完成后，项目应具备以下能力：

- 页面视觉风格统一，具备较好的产品质感。
- 用户操作流程清晰，核心路径顺畅。
- 首页、简历、岗位、AI 分析、匹配结果、历史记录等页面布局合理。
- 系统可以部署到服务器并通过域名访问。
- 后端服务、前端静态资源、数据库、对象存储等服务部署方式清晰。
- HTTPS、环境变量、日志、备份、安全策略有基础配置。
- README、演示文档、项目截图、面试讲解材料完整。
- 项目可以用于简历、面试、答辩和作品集展示。


本阶段追求：

- 好用
- 稳定

- 可演示
- 可复现
- 可讲解

不追求盲目新增大功能。

## 5. 页面优化总原则

前端页面优化应遵循以下原则：

1. 用户一进入系统就知道下一步该做什么。
2. 页面布局围绕用户任务，而不是围绕后端模块。
3. 核心页面尽量使用统一的容器、卡片、标题和状态组件。
4. AI 输出结果要结构化展示，避免大段文本堆叠。
5. 每个页面都要有清晰的主操作按钮。
6. 错误、空状态、加载状态必须有明确提示。
7. 页面风格保持专业、简洁、适合求职工具类产品。
8. 不为了炫技牺牲可读性。
9. 移动端可以适配基础布局，但不要求做完整 App 级体验。
10. 所有 UI 优化不能破坏原有业务流程。

## 7. 推荐视觉风格

项目建议采用：

```text
简洁专业的 SaaS 工具风
```

推荐风格：

- 背景：浅灰或白色
- 主色：蓝色、靛蓝或紫色
- 布局：左侧导航 + 顶部用户信息 + 内容区卡片
- 组件：圆角卡片、状态标签、分数卡片、步骤条
- 图表：少量 ECharts 展示趋势或统计
- 字体：系统默认字体即可，保持清晰
- 动效：轻量，不喧宾夺主

不建议：

- 颜色过多
- 大量渐变
- 页面信息过密
- AI 输出直接整段堆在页面上
- 每个页面风格完全不同

### v3.4 - 后端稳定性与上线前安全检查

#### 目标

在部署上线前，对后端配置、安全、日志、接口和文件访问进行检查和修复。

#### 任务拆解

- 检查生产环境配置文件。
- 检查 JWT Secret 是否安全。
- 检查 AI Key 是否通过环境变量注入。
- 检查数据库密码是否通过环境变量注入。
- 检查 CORS 配置。
- 检查文件上传大小限制。
- 检查文件类型校验。
- 检查用户文件访问权限。
- 检查接口分页。
- 检查慢查询风险。
- 检查 AI 调用超时配置。
- 检查日志是否打印敏感信息。
- 检查全局异常处理。
- 检查健康检查接口。
- 创建 `docs/security-checklist.md`。
- 更新 `docs/iteration-log/v3.4-security-check.md`。

#### 上线前安全检查

| 项目 | 要求 |
|---|---|
| JWT Secret | 不能使用默认值 |
| API Key | 不能提交到 Git |
| 数据库密码 | 不能写死 |
| CORS | 不能随意放开所有域名 |
| 文件访问 | 必须校验用户权限 |
| 日志 | 不打印 Token、密码、API Key、完整简历 |
| 上传 | 限制类型和大小 |
| HTTPS | 必须启用 |

#### 验收标准

- 生产配置和开发配置分离。
- 敏感信息不硬编码。
- 文件访问权限正确。
- CORS 策略明确。
- 日志不泄露敏感信息。
- 关键接口有错误处理。
- 本轮结果记录到 `docs/iteration-log/v3.4-security-check.md`。

## 11. 风险与取舍

### 11.1 UI 重构范围过大

不要一次性重写所有页面。优先优化首页、简历详情页、AI 匹配结果页和优化建议页。

### 11.2 部署复杂度过高

先部署单机版本，保证能访问、能跑通，再考虑复杂 CI/CD 和监控。

### 11.3 安全配置遗漏

上线前必须检查 API Key、数据库密码、JWT Secret、CORS、文件权限和日志。

### 11.4 过度包装

项目包装不能夸大，不要把未完成的功能写成已完成。

### 11.5 页面美化影响功能

UI 优化必须建立在功能稳定基础上，不要为了美观破坏原有交互。

## 12. Phase 5 开发顺序

严格按以下顺序推进：

1. v3.1 产品体验复盘与优化清单
2. v3.2 前端设计规范与组件重构
3. v3.3 核心页面 UI/UX 优化
4. v3.4 后端稳定性与上线前安全检查
5. v3.5 服务器部署与域名 HTTPS
6. v3.6 数据备份、日志与运维文档
7. v3.7 README、演示文档与截图素材
8. v3.8 简历包装与面试讲解材料

任何与产品化、部署和展示无关的大型新功能，应延后处理。
