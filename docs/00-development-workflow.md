# 开发流程文档

## 1. 文档目标

本文件用于定义项目从立项、设计、开发、测试到部署迭代的标准推进方式，作为当前项目及后续个人项目的通用开发流程规范。目标不是机械模仿大公司全部角色分工，而是在单人开发或小规模开发场景中，保留真实项目流程的关键产物与关键节点，使开发过程可控、可复盘、可展示、可持续迭代。

---

## 2. 适用范围

本流程适用于以下类型项目：

* Web 应用项目
* 前后端分离项目
* 单体架构逐步演进项目
* 以 MVP 为核心的阶段式迭代项目
* 需要后续扩展为 AI、工程化、微服务架构的项目

本流程尤其适合当前的“AI 简历优化与岗位匹配系统”，后续也可复用于其他 Java 项目。

---

## 3. 总体开发原则

### 3.1 先明确问题，再开始编码

任何开发应从需求和目标出发，而不是从技术栈出发。代码实现只是结果，前提是清楚系统要解决什么问题、服务哪些用户、当前阶段要交付什么能力。

### 3.2 优先构建 MVP 闭环

每个阶段必须形成一个可以运行、可以演示、可以复盘的最小闭环版本，而不是堆积未打通的模块。

### 3.3 先文档后实现

在进入编码前，必须先形成当前阶段的开发文档。文档不要求过度繁琐，但必须至少明确阶段目标、功能边界、页面范围、数据模型和接口清单。

### 3.4 小步快跑，持续迭代

开发过程采用迭代方式推进，每一轮迭代只解决一批明确问题，每轮结束后都要有可运行成果。

### 3.5 技术跟随业务阶段演进

技术方案要服务于当前阶段目标，不做过早设计。MVP 不追求微服务、分布式、复杂中间件，优先保证核心功能闭环。

### 3.6 每轮开发都要可复盘

每一轮迭代结束后，必须记录完成内容、遇到的问题、解决方式和后续计划，以便后期答辩、简历撰写和面试表达。

---

## 4. 标准开发流程

整个项目按以下流程推进：

### 第一步：项目立项

目标：明确项目为什么做、为谁做、做到什么程度算成功。

本阶段需要产出：

* 项目名称
* 项目背景
* 项目目标
* 目标用户
* 核心问题
* MVP 原则
* 非目标范围

输出文档：

* 项目总开发文档（初版）

---

### 第二步：阶段规划

目标：将整个项目拆分为多个可落地阶段，明确每个阶段的目标、范围与升级关系。

本阶段需要产出：

* 阶段划分
* 每阶段的目标
* 每阶段的 MVP 范围
* 每阶段新增技术栈
* 阶段之间的依赖关系

输出文档：

* 项目总开发文档（完整）

---

### 第三步：阶段开发文档编写

目标：为当前即将实施的阶段生成具体开发依据。

当前阶段开发文档至少应包含：

* 阶段目标
* 本阶段做什么、不做什么
* 核心功能清单
* 用户流程
* 页面清单
* 数据模型
* API 清单
* 技术实现说明
* 模块划分
* 开发排期
* 验收标准

输出文档：

* 当前阶段开发文档

说明：
对于单人开发，不必将 PRD、页面清单、数据模型、API 清单拆成多份独立文档，可以统一整合到“阶段开发文档”中。

---

### 第四步：开发排期与任务拆解

目标：将当前阶段开发文档进一步拆成具体迭代任务，进入实际开发。

排期原则：

* 每轮迭代只做一条或少量闭环能力
* 优先做基础能力，再做增强能力
* 先打通主流程，再补异常分支
* 前后端联调要尽早开展

本阶段需要产出：

* 迭代任务列表
* 本轮开发优先级
* 里程碑节点
* 当前版本目标

输出文档：

* 当前阶段排期计划
* 任务清单

---

### 第五步：编码实现

目标：依据当前迭代任务完成代码实现。

执行要求：

* 优先保证主流程可运行
* 所有功能均应围绕当前阶段 MVP 展开
* 避免无边界扩展
* 保持代码分层清晰
* 代码提交要有清晰 commit 信息

推荐配套实践：

* 使用 Git 管理版本
* 每个功能或修复独立提交
* 重要节点打标签或保留版本记录

输出内容：

* 后端代码
* 前端代码
* 数据库脚本/迁移脚本
* 相关配置文件

---

### 第六步：测试与联调

目标：验证当前阶段功能是否达到可用标准。

测试范围至少包括：

* 主流程测试
* 参数异常测试
* 权限测试
* 文件上传/接口异常测试
* 前后端联调测试

本阶段需要确认：

* 当前阶段核心功能全部可用
* 页面跳转正确
* 接口返回稳定
* 关键异常能被正确处理

输出内容：

* 自测记录
* Bug 修复记录
* 验收结果

---

### 第七步：部署与展示

目标：让项目具备可演示、可展示、可复现能力。

本阶段建议完成：

* 本地一键运行说明
* Docker 或 Docker Compose 部署
* README 更新
* 截图或演示说明
* 接口文档同步更新

输出内容：

* README
* 部署说明
* 运行截图/演示资料

---

### 第八步：复盘与迭代日志

目标：记录本轮阶段或版本的开发成果与问题。

每轮迭代日志建议包含：

* 版本号/迭代名称
* 本轮目标
* 完成内容
* 技术点
* 遇到的问题
* 解决方式
* 遗留问题
* 下一轮计划

输出文档：

* 迭代日志
