# v2.7 - AI 输出评估流程

状态：当前版本

## v2.7 目标

建立基础 AI 输出质量评估流程，避免 Prompt 修改后质量不可控。

v2.7 只负责“评估集、评估维度、输出记录、人工评分和 Prompt 修改规则”，不负责新增新的 AI 业务功能，不负责模型微调，不负责复杂自动化评测平台。

v2.7 完成后应满足：

- 项目中有明确的 AI 输出评估目录。
- 至少准备 3 份样例简历。
- 至少准备 3 份样例岗位描述。
- 至少覆盖简历分析、岗位描述解析、AI 匹配、优化建议、局部改写中的部分核心能力。
- 每个评估样例有输入、输出和人工评价记录。
- 评估维度包括相关性、事实一致性、具体程度、实用性、结构稳定性、可解释性和安全性。
- Prompt 修改前后可以对比输出效果。
- AI 输出问题可以被记录并反馈到 Prompt 修改规则中。
- 本轮结果记录到 `docs/iteration-log/v2.7-ai-evaluation.md`。

说明：

- v2.7 不做企业级评测平台。
- v2.7 不做模型微调。
- v2.7 不做自动打分系统。
- v2.7 不做大规模测试集。
- v2.7 不引入复杂 A/B 测试。
- v2.7 的重点是建立一个轻量、可持续、能辅助 Prompt 迭代的小型评估流程。

## v2.7.4 评估维度与评分表设计

状态：未开始

目标：

- 设计 AI 输出质量评估维度。
- 建立人工评分表。
- 让不同 Prompt 版本的输出可以进行基本对比。

任务：

- [ ] 明确评估维度。
- [ ] 为每个维度定义评分标准。
- [ ] 设计 1 到 5 分评分规则。
- [ ] 明确每个维度的扣分标准。
- [ ] 明确严重问题判定标准。
- [ ] 设计评估记录模板。
- [ ] 设计汇总报告模板。
- [ ] 将模板写入 `docs/evaluation/evaluation-notes.md`。
- [ ] 将汇总模板写入 `docs/evaluation/reports/evaluation-report-v1.md`。

建议评估维度：

| 维度 | 说明 |
|---|---|
| relevance | 相关性：是否围绕简历和岗位 |
| factualConsistency | 事实一致性：是否没有编造经历 |
| specificity | 具体程度：建议是否具体 |
| usefulness | 实用性：是否有助于简历优化 |
| structureStability | 结构稳定性：是否符合 JSON 结构 |
| explainability | 可解释性：结论是否有依据 |
| safety | 安全性：是否避免虚假、敏感或误导内容 |

建议评分规则：

| 分数 | 含义 |
|---|---|
| 5 | 表现优秀，可以直接采用 |
| 4 | 表现较好，只需轻微调整 |
| 3 | 基本可用，但存在明显改进空间 |
| 2 | 问题较多，需要修改 Prompt |
| 1 | 不可用，存在严重错误 |

严重问题示例：

| 问题 | 说明 |
|---|---|
| 编造经历 | 生成用户不存在的项目、实习或技能 |
| 结构错误 | 输出无法被系统解析 |
| 建议空泛 | 建议无法指导实际修改 |
| 依据缺失 | 匹配结论没有说明来源 |
| 安全风险 | 暴露敏感信息或误导用户 |

验收标准：

- 评估维度明确。
- 每个维度有评分规则。
- 有人工评估记录模板。
- 有汇总报告模板。
- 明确严重问题判定标准。
- 本任务不调用 AI。
- 本任务不实现自动化评分。

## v2.7.6 评估问题汇总与 Prompt 修改规则

状态：未开始

目标：

- 对已记录的 AI 输出进行人工评估。
- 汇总常见问题。
- 形成 Prompt 修改规则，指导后续迭代。

任务：

- [ ] 使用评分表评估 AI 输出。
- [ ] 给每个输出记录各维度评分。
- [ ] 标记是否存在严重问题。
- [ ] 汇总结构错误问题。
- [ ] 汇总事实不一致问题。
- [ ] 汇总建议空泛问题。
- [ ] 汇总依据不足问题。
- [ ] 汇总安全风险问题。
- [ ] 总结 Prompt 修改方向。
- [ ] 形成 Prompt 修改规则。
- [ ] 更新 `docs/evaluation/evaluation-notes.md`。
- [ ] 更新 `docs/evaluation/reports/evaluation-report-v1.md`。

建议问题分类：

| 问题类型 | 说明 |
|---|---|
| FORMAT_ERROR | 输出格式错误 |
| HALLUCINATION | 编造经历或事实 |
| VAGUE_SUGGESTION | 建议空泛 |
| MISSING_EVIDENCE | 缺少依据 |
| OVER_OPTIMIZATION | 改写过度 |
| UNSAFE_CONTENT | 存在安全风险 |
| LOW_RELEVANCE | 与岗位或简历相关性低 |

Prompt 修改规则示例：

- 如果输出经常编造经历，在 Prompt 中进一步强调“只能基于输入内容”。
- 如果建议空泛，要求输出必须包含目标简历部分、问题、修改建议和依据。
- 如果结构不稳定，减少自由文本，强化 JSON 示例。
- 如果匹配依据不足，要求每个结论至少引用一条简历证据或岗位证据。
- 如果改写过度，要求保留事实边界并输出 caution。

验收标准：

- 至少完成 3 组 AI 输出的人工评估。
- 每组评估有维度评分。
- 常见问题已分类。
- Prompt 修改规则已记录。
- 评估报告已更新。
- 不实现复杂自动化评估平台。
- 不做模型微调。
