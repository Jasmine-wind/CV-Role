# v3.1 架构现状审查与领域边界收敛

## 目标

在进入 Phase 4 架构演进前，审查当前项目的后端模块、前端模块、长耗时任务、存储、安全和部署配置，形成后续调整优先级。

## 完成内容

| 小任务 | 状态 | 说明 |
|---|---|---|
| v3.1.1 后端模块结构审查 | 已完成 | 梳理 `common / config / security / infra / module` 边界，记录体量偏大的 Controller、Service 和后续拆分方向 |
| v3.1.2 前端模块结构审查 | 已完成 | 梳理页面、路由、API、Store、组件结构，确认 `ResumeView.vue` 和 `AiJobMatchView.vue` 是前端优先拆分对象 |
| v3.1.3 长耗时任务现状审查 | 已完成 | 梳理解析、AI、匹配、建议、改写、Embedding 执行方式，确认后续优先采用单体内异步任务 |
| v3.1.4 存储、安全与部署现状审查 | 已完成 | 梳理文件存储、上传限制、权限校验、敏感配置、CORS、日志脱敏和部署配置问题 |
| v3.1.5 架构审查日志 | 已完成 | 汇总当前架构优点、问题清单、Phase 4 后续调整优先级和不做微服务拆分原因 |

## 验证结果

- 已更新 `docs/architecture-review.md`，记录 v3.1.1 到 v3.1.5 审查结果。
- 已更新 `docs/tasks/phase-4-task-list.md`，将 v3.1 标记为已完成，并把当前版本推进到 v3.2。
- 本轮为文档审查和任务收口，不修改后端代码、前端代码或数据库结构。

## 当前不足

- v3.1 只形成审查结论，尚未实际拆分大类、组件或异步任务。
- `SecurityConfig` 默认放行策略、生产 Profile、CORS 环境化、MinIO 实现、文件删除一致性仍需在后续版本处理。
- 长耗时任务只完成分类和优先级确认，还没有落地线程池、任务状态流转和前端轮询。

## 结果

v3.1 已完成架构现状审查，可以进入 v3.2 面向领域的包结构整理。后续应继续保持小步低风险原则，不做微服务拆分，不改接口路径，不做大规模数据库结构调整。
