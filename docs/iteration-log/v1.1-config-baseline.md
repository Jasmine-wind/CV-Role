# v1.1 Phase 2 基线检查与配置整理

## 1. 本轮目标
确认 Phase 1 MVP 在进入 Phase 2 后仍可构建和测试，整理后端与前端配置边界，并明确开发环境、测试环境、敏感配置和本地文件存储现状。

本轮不新增业务功能，不引入 Flyway、OpenAPI、CI 或复杂部署能力。

## 2. 本轮完成内容
- 检查后端配置文件现状
- 检查前端环境变量读取方式
- 检查 PostgreSQL 配置来源
- 检查 MinIO 当前使用状态
- 检查 AI Key 是否存在硬编码风险
- 保留 `application.yaml` 作为后端公共配置
- 新增 `application-dev.yaml` 作为本地开发配置
- 新增 `application-test.yaml` 作为测试环境配置规划
- 将 PostgreSQL 连接配置从公共配置中拆到开发配置
- 将 AI base URL、模型、温度、超时和 token 限制改为可由环境变量覆盖
- 将本地文件存储路径改为可由 `LOCAL_STORAGE_BASE_DIR` 覆盖
- 新增根目录 `.env.example`
- 新增 `web/.env.development`
- 新增 `web/.env.production`
- 更新 README 中的环境变量、profile 和前端环境配置说明
- 更新 Phase 2 任务清单，将 v1.1 标记为已完成，下一步切换到 v1.2

## 3. 配置边界
- `backend/src/main/resources/application.yaml`：公共配置，包括服务端口、profile 默认值、multipart、MyBatis-Plus、JWT、AI 公共参数和本地存储公共参数
- `backend/src/main/resources/application-dev.yaml`：本地开发 PostgreSQL 配置和开发日志级别
- `backend/src/main/resources/application-test.yaml`：测试环境数据库、JWT、AI 占位值和测试上传目录
- `.env.example`：可提交的环境变量模板，只包含占位符
- `.env`：本地真实环境变量文件，不提交
- `web/.env.development`：前端开发环境 API 地址
- `web/.env.production`：前端生产构建 API 地址
- `web/.env.local`：本地前端覆盖配置，不提交

## 4. 检查结论
- Phase 1 当前仍使用本地 `uploads/` 文件存储，不需要启动 MinIO。
- PostgreSQL 开发配置位于 `application-dev.yaml`，默认数据库为 `ai_resume_optimizer`。
- 测试环境配置已预留 `application-test.yaml`，后续 v1.6 做 API 集成测试时可继续完善。
- AI Key 不硬编码在代码或配置中，通过 `DASHSCOPE_API_KEY` 注入。
- `.gitignore` 已覆盖 `.env`、`.env.local`、`.env.*.local`、`.idea/`、`target/`、`node_modules/` 和 `dist/`。
- `.env.example`、`web/.env.development` 和 `web/.env.production` 不包含真实敏感信息。

## 5. 验证记录
- 已运行后端 `./mvnw test`。
- 已运行前端 `npm run build`。
- 前端构建通过。
- 已确认后端根配置可以加载默认 `dev` profile。
- 已确认前端仍通过 `VITE_API_BASE_URL` 读取 API 地址。

## 6. 当前不足
- 测试环境仍使用 PostgreSQL 配置占位，后续 v1.6 做集成测试时需要明确测试数据库初始化方式。
- 数据库迁移仍依赖 `db/init` 下的手动 SQL，后续 v1.3 再引入 Flyway。
- 错误码、参数校验和异常返回格式尚未系统增强，后续 v1.2 处理。
- 本地依赖服务编排和 CI 尚未整理，后续 v1.8 处理。
