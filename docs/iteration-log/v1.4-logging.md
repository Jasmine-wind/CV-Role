# v1.4 - 日志规范与敏感信息保护

## 1. 目标

建立基础日志规范，使日志可以帮助定位注册、登录、上传、解析、AI 分析和岗位匹配等关键流程问题，同时避免泄露密码、JWT、AI Key、完整简历原文、AI Prompt 和 AI 返回全文。

## 2. 本轮完成内容

- 检查现有日志使用情况，确认主要日志集中在全局异常处理，业务主流程缺少过程日志。
- 新增 `RequestIdFilter`，为请求写入 MDC `requestId`，并通过响应头 `X-Request-Id` 返回。
- 新增 `LogSanitizer`，对日志中的 Token、API Key、密码等敏感字段做基础脱敏，并限制错误原因长度。
- 配置控制台日志格式，统一包含时间、级别、requestId、logger 和日志内容。
- 注册、登录流程增加成功和失败日志，不记录密码、登录原始凭证和 JWT。
- 简历上传流程增加开始、成功和保存失败日志，只记录用户、文件类型、大小、存储类型等元信息。
- 简历解析流程增加开始、成功和失败日志，只记录解析文本长度，不输出完整简历原文。
- AI 分析流程增加开始、成功和失败日志，只记录模型、分数、错误原因等元信息，不输出 Prompt、API Key 和 AI 返回全文。
- AI Client 增加调用开始、HTTP 失败、成功、超时、中断和 IO 异常日志，不输出请求体、响应体和授权头。
- 岗位匹配流程增加开始和完成日志，便于定位用户、简历、岗位和匹配分数。
- 全局异常处理增加业务异常、文件存储异常和 AI 调用异常日志，并对异常消息做基础脱敏。
- 显式提供 JWT 项目的 `UserDetailsService` 边界，避免 Spring Security 输出自动生成的开发密码。
- CORS 暴露 `X-Request-Id` 响应头，便于前端或调试工具关联请求日志。

## 3. 日志级别约定

| 级别 | 使用场景 |
|---|---|
| `info` | 核心业务流程开始、成功、完成等正常关键节点 |
| `warn` | 参数、业务、上传、解析、AI 调用等可预期失败 |
| `error` | 未知异常或需要开发者排查的系统级异常 |

## 4. 敏感信息边界

本轮明确不在日志中输出：

- 用户密码。
- JWT 和 Bearer Token。
- AI API Key。
- 完整简历原文。
- AI Prompt。
- AI 返回全文。
- 登录时提交的原始账号凭证。

可记录的信息仅限于排查所需元信息，例如 `userId`、`resumeId`、`jobId`、文件类型、文件大小、模型名、HTTP 状态码、文本长度和脱敏后的错误原因。

## 5. requestId 行为

- 如果请求头带有合法的 `X-Request-Id`，后端沿用该值。
- 如果请求头没有 requestId，后端自动生成 UUID。
- requestId 写入日志 MDC，并通过响应头 `X-Request-Id` 返回。
- 当前版本不把 requestId 写入 API 响应体，后续如前端需要可再扩展。

## 7. 遗留说明

- 当前日志仍是控制台输出，没有引入外部日志采集平台。
- requestId 已覆盖 Servlet 请求链路，但异步任务和跨服务追踪不在 Phase 2 范围内。
- 日志脱敏是基础防护，后续如果增加更多敏感字段，需要同步扩展 `LogSanitizer`。
