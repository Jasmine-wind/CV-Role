# v4.10 - 建议驱动的局部改写体验增强

## 目标

将“局部改写”从手动复制原文的孤立入口，升级为从岗位优化建议出发的闭环流程：用户点击某条建议后，系统准备岗位关键词、候选简历片段、改写目标和表达风格，用户确认片段后生成局部改写。

边界：不新增数据库表，不修改后端业务主流程，不自动覆盖原始简历，不提供“应用到简历”，不做在线简历编辑器。

## 完成内容

- 新增 `GET /api/rewrite-suggestions/context?suggestionId=...&suggestionIndex=...`，返回当前建议、简历、目标岗位、匹配结果、岗位关键词、候选片段、默认改写目标和表达风格。
- 新增 `RewriteContextVO`、`RecommendedRewriteSectionVO`、`RewriteSourceRefVO`，上下文模型不依赖新表。
- 局部改写请求兼容新增 `sourceText`、`suggestionId`、`matchId`、`rewriteGoal`、`jobKeywords`、`tone`、`lengthLimit`，旧 `originalText` 手动输入仍可用。
- 候选片段从 `ResumeParseResult.structuredJson` 的 `structuredData` / `displayModel` 中规则推荐，按建议类型、目标模块、岗位关键词命中、内容长度和 sourceRef 计算分数，最多返回 5 条。
- 改写 Prompt 加入改写目标、岗位关键词、表达风格和长度限制，并继续强调只改写用户确认片段、不能编造事实。
- 前端匹配与优化页从建议卡片进入改写弹窗，展示当前建议、岗位关键词、候选原文、改写目标、表达风格、原文编辑区、生成结果对比和复制按钮。
- 历史聚合继续使用 `LOCAL_REWRITE`，并增强局部改写详情中的关联建议展示；岗位优化建议列表摘要避免直接展示 JSON 字符串。
- AI 历史详情已调整为按结果类型展示用户可读报告，普通用户侧不展示 model、promptVersion、recordId、sourceType 或原始 JSON。
- 局部改写、历史建议和优化报告中的长内容已支持展开 / 收起，避免页面被大量改写结果撑长。
- 简历删除确认已补充关联清理提醒，明确匹配分析、岗位优化建议、局部改写、AI 历史关联记录、向量索引和上传文件会随简历删除一起清理。
- 更新 v4.10 任务清单，记录自动验证和人工验收待执行项。

结果：

- 后端编译通过。
- 局部改写服务、Prompt、AI 历史聚合和 Phase1 API 集成相关测试通过。
- 前端类型检查和 Vite 构建通过。
- 旧手动局部改写入口保持兼容，空原文仍返回“原文片段不能为空”。

## 当前不足

- 候选片段推荐为规则优先，不调用 AI 自动选段；如果简历结构化解析质量不足，前端会退回手动粘贴原文。
- 本轮未接入真实浏览器账号和真实 AI 服务做端到端人工验收，需要用户按任务清单执行最终验收。
- 新增请求参数 `rewriteGoal/jobKeywords/tone/lengthLimit` 当前用于 Prompt，不新增数据库列持久化。
- 简历删除确认只负责前端提醒；真实关联清理仍以后端 `DELETE /api/resumes/{id}` 的删除链路为准。

## 结果

v4.10 已完成建议驱动的局部改写闭环：岗位优化建议可以直接进入局部改写，上下文由后端准备，前端支持候选片段确认、改写目标选择、结果对比、复制和长内容展开收起，生成结果进入 AI 历史；简历删除前也会明确提醒关联 AI 结果和改写数据将同步清理。
