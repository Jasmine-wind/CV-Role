# v1.6 - 关键 API 集成测试

## 1. 目标

为 Phase 1 MVP 主流程中的关键 API 增加接口级自动化测试，验证认证边界、统一错误响应和核心接口路由行为。

## 2. 本轮完成内容

- 新增 `Phase1ApiIntegrationTest`。
- 使用 `@WebMvcTest + MockMvc` 作为接口级测试方式。
- 使用 `test` profile 加载测试配置。
- 通过 `@MockitoBean` mock 业务 Service 和 JWT Provider，避免依赖真实数据库、文件存储和外部 AI 服务。
- 导入 `SecurityConfig`、JWT 过滤器、统一异常处理和 requestId 过滤器，覆盖真实 Web 安全链路。
- 将 `RequestIdFilter` 顺序提前，保证认证失败这类安全过滤器提前返回的响应也带 `X-Request-Id`。

## 3. 覆盖范围

| 接口范围 | 覆盖内容 |
|---|---|
| 认证接口 | 注册、登录成功响应 |
| 当前用户接口 | 未登录 401、登录后读取当前用户 |
| 简历接口 | 上传、列表、详情、跨用户/无权限资源错误、解析触发、解析结果查询 |
| AI 分析接口 | 触发 AI 分析、查询 AI 分析结果 |
| 岗位接口 | 岗位列表、岗位详情 |
| 岗位匹配接口 | 触发岗位匹配、查询匹配结果 |
| 历史记录接口 | 历史列表、历史详情 |

## 4. 测试边界

- 本轮是接口级测试，不做真实数据库写入。
- 文件上传接口使用 MockMultipartFile，不落真实文件。
- AI 分析接口 mock `ResumeAnalysisService`，不调用真实模型。
- JWT 认证通过 mock `JwtTokenProvider` 固定解析用户身份。
- 用户隔离通过业务 Service 抛出 `BusinessException` 模拟，验证 Controller 和统一异常处理的响应结构。

## 6. 遗留说明

- 本轮重点是 Controller、安全链路和统一响应结构，不替代未来更重的端到端测试。
- 当前 API 测试不依赖真实数据库，因此数据库级数据隔离和事务回滚不是本轮重点。
- 后续如需要覆盖真实持久化链路，可在 v1.8 或后续阶段基于独立测试库补充更重的集成测试。
