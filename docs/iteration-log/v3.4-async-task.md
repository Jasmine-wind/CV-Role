# v3.4 长耗时任务异步化设计

## 目标

为简历解析、AI 诊断、岗位解析、匹配分析、优化建议和 Embedding 等长耗时任务建立单体内异步任务基础设施，避免后续业务改造时每个接口各自实现线程池、任务状态和轮询逻辑。

## 完成内容

| 小任务 | 状态 | 说明 |
|---|---|---|
| v3.4.1 长耗时任务异步化方案设计 | 已完成 | 已明确耗时接口、异步化优先级、任务类型、状态枚举、结果引用和旧同步接口兼容策略 |
| v3.4.2 单体内线程池配置 | 已完成 | 已新增 `applicationTaskExecutor`、`app.async` 配置和线程池测试 |
| v3.4.3 任务状态字段与状态流转设计 | 已完成 | 已新增 `async_tasks`、`module/task`、状态服务和 `GET /api/tasks/{taskId}` |
| v3.4.4 前端轮询策略设计 | 已完成 | 已新增任务状态 API、轮询工具和简历页任务状态面板 |
| v3.4.5 异步任务错误处理策略 | 已完成 | 已新增统一错误码和异步任务失败处理器 |
| v3.4.6 v3.4 文档与验证 | 已完成 | 已完成文档、验证和手动验收收口 |

## 验证结果

- `./mvnw test -Dtest=AsyncTaskConfigTest`：1 个测试通过。
- `./mvnw test -Dtest=AsyncTaskServiceImplTest,AsyncTaskConfigTest`：7 个测试通过。
- `./mvnw test -Dtest=AsyncTaskFailureHandlerImplTest,AsyncTaskServiceImplTest,AsyncTaskConfigTest`：9 个测试通过。
- `./mvnw test -DskipTests`：后端主代码和测试代码编译通过。
- `npm run build`：前端类型检查和 Vite 构建通过。
- 手动验收已完成：现有同步上传、解析、诊断主流程不被破坏，任务状态查询和前端轮询基础能力可用。

## 当前不足

- 旧同步接口仍会阻塞 Web 请求线程，尚未接入统一任务提交和后台执行。
- 当前还没有异步任务提交接口，`async_tasks` 暂作为基础设施和后续业务改造入口。
- 前端已具备轮询工具和简历页状态面板，但还没有全局任务 Store。
- Embedding 已有 chunk 级状态，但缺少任务级聚合状态。
- 错误处理器尚未被具体业务 worker 调用，需要在 v3.5 首批异步任务落地时接入。

## 结果

v3.4 已完成长耗时任务异步化基础设计和初步落地：线程池、任务表、状态查询接口、前端轮询工具、任务状态面板和失败处理器均已具备。当前完成的是异步基础设施闭环，完整业务异步提交和 worker 接入留到 v3.5。
