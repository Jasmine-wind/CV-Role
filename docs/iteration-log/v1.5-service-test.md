# v1.5 - Service 层单元测试

## 1. 目标

为核心业务逻辑补充 Service 层单元测试，覆盖注册登录、简历上传校验、文本提取、结构化解析、岗位匹配和优化建议生成，提升后续修改时的回归信心。

## 2. 本轮完成内容

- 确认当前 `spring-boot-starter-test` 已包含 JUnit 5、AssertJ、Mockito 和 Spring Test，不需要额外引入测试依赖。
- 新增 `AuthServiceImplTest`。
- 扩展 `ResumeServiceImplTest`。
- 新增 `ResumeTextExtractionServiceImplTest`。
- 复用已有 `ResumeStructureParseServiceImplTest`、`JobMatchServiceImplTest`、`JobMatchSuggestionServiceImplTest`、`JobMatchResultServiceImplTest`、`HistoryServiceImplTest`、AI Client 相关测试。

## 3. 覆盖范围

| 测试类 | 覆盖内容 |
|---|---|
| `AuthServiceImplTest` | 注册成功、用户名重复、登录成功、密码错误 |
| `ResumeServiceImplTest` | 上传元数据保存、非法扩展名、文件大小限制、保存失败清理已上传文件、删除级联清理 |
| `ResumeTextExtractionServiceImplTest` | DOCX 文本提取、空文件类型、文件读取失败包装 |
| `ResumeStructureParseServiceImplTest` | 简历文本结构化解析基础行为 |
| `JobMatchServiceImplTest` | 技能匹配算法、空技能、逗号分隔技能、岗位技能为空 |
| `JobMatchSuggestionServiceImplTest` | 技能缺口建议、优势突出建议、低匹配度建议、空匹配结果 |
| `JobMatchResultServiceImplTest` | 岗位匹配结果保存、复用、异常边界 |

## 4. 测试边界

- Service 单测优先使用 Mockito mock Mapper、存储服务和外部依赖。
- 不依赖真实 AI 服务。
- 不依赖真实文件系统。
- DOCX 文本提取测试使用内存构造的 Word 文档。
- 真实 AI smoke test 保持跳过策略，仅在配置真实 Key 时用于手动验证。
