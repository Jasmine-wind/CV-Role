# v2.11 - 主流程与边界收敛

## 目标

基于当前仓库完成《AI 简历优化与岗位匹配系统》主流程边界收敛，明确“简历资产 + 用户粘贴目标岗位 JD”为主线，并检查 Controller / Service、Prompt、报告、历史回看、DTO / VO / Entity 等关键边界。

边界：不做微服务拆分，不大规模重构数据库结构，不新增岗位爬取，不新增 AI 能力，不修改既有接口路径，不把岗位优化报告做成新的 AI 生成功能。

## 完成内容

- 工作台从按钮集合收敛为主流程入口，展示简历、目标岗位、匹配分析、岗位优化建议、最近 AI 结果和下一步推荐。
- 目标岗位主流程明确为用户粘贴真实 JD；`job_descriptions` 增加 `sourceType`，区分 `USER_INPUT`、`PRESET` 和 `CRAWLED`。
- 后端文案和接口说明从“岗位描述 / AI 岗位匹配”收敛为“目标岗位 / 匹配分析 / 岗位优化建议”。
- Prompt 收拢到 `backend/src/main/resources/prompts/`，按简历诊断、目标岗位解析、匹配分析、岗位优化建议、局部改写拆分，并标记版本。
- 岗位优化报告保持聚合已有匹配、建议、改写和采纳状态，不重新调用 AI，不补造依据。
- AI 结果回看明确只查询已保存结果，不触发新的 AI 生成。
- DTO / VO / Entity 边界完成检查，关键 Controller 返回 VO，请求参数使用 DTO，未发现直接返回 Entity 的关键接口。
- 文档同步更新产品结构、项目主线和 Codex 上下文边界。

## 验证结果

已执行：

```bash
cd backend
./mvnw -Dtest=*,!ServeApplicationTests test
./mvnw -q -DskipTests package

cd web
npm run build
```

结果：

- 后端业务测试通过：265 个测试通过，2 个跳过。
- 后端跳过测试打包通过。
- 前端构建通过。
- 完整 `./mvnw test` 仅 `ServeApplicationTests.contextLoads` 失败，原因是本地 PostgreSQL 用户 `dawn` 密码认证失败，属于本地数据库配置问题，不是本轮业务测试失败。

## 当前不足

- 基础岗位匹配仍作为旧能力保留，后续需要继续弱化其在主流程中的存在感。
- `ServeApplicationTests` 依赖本地 PostgreSQL，后续 Phase 4 可考虑补测试 profile 或容器化测试配置。
- `sourceType=CRAWLED` 仅作为边界枚举保留，当前不实现爬取或自动采集。

## 结果

v2.11 已完成进入 Phase 4 前的主流程与边界收敛：项目主线、岗位来源、AI 功能边界、报告聚合边界、历史回看边界和 DTO / VO / Entity 边界均已明确，可以继续进入 Phase 4 架构演进任务。
