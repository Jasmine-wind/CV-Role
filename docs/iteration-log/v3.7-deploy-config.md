# v3.7 可部署配置与环境隔离

## 目标

整理本地、开发测试和生产部署配置边界，避免本地路径、本地默认密码、调试日志和开发 Profile 被直接带入部署环境。v3.7 只做配置与部署准备，不新增业务功能，不进行真实服务器部署。

## 关键改动

- `application.yaml` 默认 Profile 调整为 `local`，公共配置继续保留在根配置文件中。
- 新增 `application-local.yaml`，用于本机开发环境，支持本地 PostgreSQL、本地文件存储、AI / Embedding 和日志级别配置。
- 新增 `application-prod.yaml`，用于生产部署环境，数据库、JWT、AI、Embedding、存储目录等关键值均通过环境变量注入。
- `application-dev.yaml` 保留为开发测试服务器配置入口，并将日志级别改为环境变量可控。
- `.env.example` 按应用基础、数据库、Redis、JWT、AI、Embedding、异步任务、文件存储、MinIO 和日志分类整理。
- 新增 `web/.env.example`，说明前端 `VITE_API_BASE_URL`。
- `docker-compose.yml` 新增 Redis 服务，保留 PostgreSQL / pgvector 和 MinIO 依赖服务。
- 新增 `deploy/nginx/ai-resume.conf` 和 `deploy/nginx/README.md`，作为后续部署的 Nginx 草案。
- 新增 `docs/deployment.md`，整理服务器准备、环境变量、构建、启动、部署后验收、安全检查和回滚清单。
- README 和 `docs/architecture-review.md` 已同步配置、Compose、Nginx 和部署文档说明。

## 当前不足

- 未进行真实服务器部署，v3.7 只完成可部署配置准备。
- 本地未安装 `nginx`，未执行 `nginx -t`。
- 仓库暂无后端 / 前端应用 Dockerfile，Compose 仍只用于依赖服务。
- MinIO 仍是对象存储接入预留，当前后端上传链路继续使用 local 存储。
- Redis 当前只作为依赖预留，后端运行路径尚未依赖 Redis。
- `LOG_FILE_PATH` 已作为变量预留，当前后端主要完成日志级别环境化。
- CORS 仍在后续部署 / 反向代理配置阶段继续配置化。
- HTTPS、systemd 服务、应用容器镜像和正式域名绑定留到后续阶段。
