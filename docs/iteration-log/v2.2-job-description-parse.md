# v2.2 - 岗位描述输入与结构化解析

## 目标

实现岗位描述输入、保存、AI 结构化解析和前端展示闭环，为后续“简历 + 岗位描述”的 AI 匹配分析提供数据基础。

v2.2 只做岗位描述输入与结构化解析，不做简历与岗位 AI 匹配。

## 完成内容

- 新增 `job_descriptions` 表迁移脚本。
- 新增 `JobDescription` 实体和 `JobDescriptionMapper`。
- 实现 `POST /api/job-descriptions`，保存当前用户提交的岗位描述。
- 实现 `GET /api/job-descriptions`，返回当前用户已提交的岗位描述列表。
- 实现 `GET /api/job-descriptions/{id}`，返回岗位描述原文、解析状态、结构化结果、模型名称、Prompt 版本和错误信息。
- 实现 `POST /api/job-descriptions/{id}/parse`，触发当前用户岗位描述的 AI 结构化解析。
- 将 `/api/job-descriptions/**` 加入认证保护，保证用户只能访问自己的岗位描述。
- 新增 `job_description_parse_v1` Prompt，输入为岗位描述原文，输出为受控 JSON。
- 输出字段包括 `jobTitle`、`requiredSkills`、`bonusSkills`、`experienceSignals`、`responsibilities`、`keywords`、`summary`。
- Prompt 要求不编造岗位描述中不存在的信息，并区分必备技能和加分技能。
- 新增岗位描述输出解析器，处理非 JSON、非对象、字段类型错误、列表长度和单条文本长度限制。
- AI 解析成功时保存结构化结果、模型名称、Prompt 版本和 `SUCCESS` 状态。
- AI 调用失败或输出解析失败时保存 `FAILED` 状态和错误信息，并清空结构化结果。
- 新增前端岗位描述列表页、输入页和详情页。
- 新增 `/job-descriptions`、`/job-descriptions/new` 和 `/job-descriptions/:id` 路由，并使用登录守卫保护。
- 前端支持查看已提交岗位描述、提交岗位描述、触发解析、展示解析状态和结构化解析结果。
- 前端展示职位名称、岗位摘要、必备技能、加分技能、经验信号、职责内容和关键词。
- 修复岗位描述详情页首次进入不加载数据的问题。
- 将岗位描述解析请求超时时间调整为 120 秒。


已执行后端编译：

```bash
cd backend
./mvnw -DskipTests compile
```

已执行前端构建：

```bash
cd web
npm run build
```

已完成本地手动联调：

- 前端可以提交岗位描述并跳转详情页。
- 前端可以从岗位描述列表重新打开已提交记录。
- 前端可以触发岗位描述解析。
- 岗位描述解析可以成功返回结构化结果。
- 解析结果可以在前端详情页展示。

## 结果

v2.2 已完成岗位描述输入与结构化解析闭环。当前系统已经可以保存岗位描述原文，调用 AI 抽取岗位要求，并在前端展示结构化解析结果。

下一步进入 v2.3，基于简历解析结果和岗位描述解析结果实现 AI 匹配分析。
