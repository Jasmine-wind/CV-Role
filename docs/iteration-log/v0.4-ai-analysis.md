## 4. 遇到的问题
- 当前真实 AI 服务的 API Key、base-url 和模型参数依赖本地环境变量，不能写死在代码里。
- AI 返回内容可能不是合法 JSON，或者字段缺失、评分越界。
- 重复分析时需要覆盖旧结果，避免同一份简历产生多条分析记录。
- AI 调用失败或返回格式异常时，需要保存失败状态，但不能保存脏的评分和建议内容。
- 查询接口需要返回完整列表字段，不能把数据库里的 JSON 字符串直接暴露给前端。
- 真实 AI 分析可能因为简历解析文本过长、PDF 换行噪声和模型响应慢而超时。
- 前端 Axios 默认 10 秒超时，真实 AI 分析请求可能还未完成就被浏览器端中断。
- 删除简历时如果只删除解析结果和简历主表，会漏掉 AI 分析等后续关联数据。

## 5. 解决方式
- 在 `application.yaml` 中统一通过环境变量读取 AI 配置。
- 使用 Prompt 明确要求只输出 JSON，并限制字段结构。
- 对缺失字段使用兜底文本，对评分限制在 0 到 100。
- 对非 JSON 输出抛出业务异常，后续分析服务不应保存脏数据。
- 在 `ResumeAnalysisServiceImpl` 中按 `resume_id` 查询旧分析记录，有旧记录则更新，没有则新增。
- 分析失败时清空评分、优势、问题和建议摘要，只保留 `FAILED`、模型名称、Prompt 版本和错误信息。
- 将进入 Prompt 的原始解析文本压缩到 6000 字符，结构化 JSON 压缩到 3000 字符。
- 对 PDF 提取造成的短行断裂做基础合并，减少无意义换行对模型理解的影响。
- 为 AI 请求增加 `max_tokens` 配置，默认限制为 800，降低长输出导致的等待时间。
- 将默认 AI 调用超时时间调整为 90 秒，并对超时返回更明确的错误提示。
- 将前端 AI 分析请求 timeout 单独调整为 120 秒，避免影响普通接口。
- 使用独立页面状态区分解析结果和 AI 分析展示，避免两个按钮互相覆盖状态。
- 在 `ResumeServiceImpl` 中集中封装关联数据删除逻辑，先删 AI 分析和解析结果，再删简历主表和文件。

## 6. 当前不足
- 当前 Prompt 仍是第一版，后续可根据更多真实简历样本继续微调。
- 当前长文本处理只做轻量压缩和清洗，不做分片、多轮总结或 RAG。
- 真实 AI smoke test 需要配置 live 环境变量后才能执行。
