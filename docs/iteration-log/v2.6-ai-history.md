# v2.6 - AI 结果持久化与历史回看

## 目标

统一管理简历诊断、目标岗位解析、匹配分析、岗位优化建议和局部改写结果，便于用户回看、复盘和后续迭代。

v2.6 只做已有 AI 结果的统一查询、回看和追踪，不新增 AI 生成能力，不做 AI 输出质量评估，不做 Embedding、pgvector、RAG 或多轮对话。

## 完成内容

- 梳理现有 AI 结果来源：`resume_ai_analyses`、`job_descriptions`、`ai_job_match_results`、`ai_resume_suggestions`、`ai_rewrite_suggestions`。
- 确认五类 AI 结果均已具备模型名称、Prompt 版本、状态字段、错误信息、创建时间和更新时间。
- 明确 v2.6 AI 结果类型：`RESUME_DIAGNOSIS`、`TARGET_JOB_PARSE`、`MATCH_ANALYSIS`、`JOB_OPTIMIZATION_SUGGESTION`、`LOCAL_REWRITE`。
- 明确 AI 结果状态统一按 `PENDING`、`SUCCESS`、`FAILED` 理解，各表保留现有业务状态字段名。
- 确认当前无需新增数据库迁移脚本。
- 补齐 AI 结果详情 VO 的 `createdAt` 字段，便于历史列表和详情页统一展示生成时间。
- 明确 v2.6 采用聚合查询方案，不新建 `ai_result_records` 表，不复制大段 AI 输出内容。
- 明确新增独立 `/api/ai-results` 接口族，不替换现有 `/api/history` 简历维度历史接口。
- 明确 AI 历史列表字段、详情字段、筛选参数、排序规则和用户隔离规则。
- 新增 `AiHistoryController`、`AiHistoryService` 和 `AiHistoryServiceImpl`。
- 新增 `AiResultRecordVO`、`AiResultPageVO` 和 `AiResultDetailVO`。
- 新增 `GET /api/ai-results`，聚合简历诊断、目标岗位解析、匹配分析、岗位优化建议和局部改写五类 AI 结果。
- AI 历史列表支持按 `resultType`、`resumeId`、`jobDescriptionId`、`status`、`page`、`size` 查询。
- AI 历史列表按 `updatedAt` 倒序排列，缺失时使用 `createdAt`。
- 新增 `GET /api/ai-results/{resultType}/{recordId}`，通过 `resultType + recordId` 查询某条 AI 结果详情。
- AI 历史详情 `content` 按类型返回结构化内容，不返回 API Key、完整 Prompt 或敏感配置。
- 当前用户只能看到自己拥有的简历和目标岗位关联结果。
- 无权限访问和记录不存在统一返回“AI 结果不存在”，避免泄露他人记录存在性。
- 将 `/api/ai-results/**` 纳入 Spring Security 鉴权路径。
- 新增服务层测试覆盖五类结果聚合、筛选、无权限筛选空列表、非法类型报错、匹配分析详情和跨用户详情访问校验。
- 更新 WebMvc 集成测试覆盖 AI 历史列表和详情接口。
- 复用 `/history` 路由，将前端页面升级为 AI 历史结果页面。
- 在 `web/src/api/history.ts` 中新增 `getAiResultPage` 和 `getAiResultDetail`。
- 在 `web/src/types/history.ts` 中新增 `AiResultRecord`、`AiResultPage` 和 `AiResultDetail` 类型。
- 重写 `web/src/views/history/HistoryView.vue`，接入 AI 历史列表和详情接口。
- 前端支持按 AI 结果类型、状态、简历 ID、目标岗位 ID 筛选。
- 前端支持分页、加载状态、空状态、接口错误提示和详情抽屉。
- 前端列表展示结果类型、标题、摘要、状态、关联简历、关联目标岗位、模型、Prompt 版本和更新时间。
- 前端详情展示元数据、错误信息和结构化 `content`。
- 前端提供跳转到简历、目标岗位和匹配与优化页面的动作。
- 前端不展示 API Key、完整 Prompt 等敏感信息。
- 已压缩 `docs/tasks/phase-3-task-list.md` 中的 v2.6 任务内容。

## 验证结果

已执行后端编译：

```bash
cd backend
./mvnw -DskipTests compile
```

已执行 AI 历史列表服务测试和 API 集成测试：

```bash
cd backend
./mvnw -Dtest=AiHistoryServiceImplTest,Phase1ApiIntegrationTest test
```

已执行前端构建：

```bash
cd web
npm run build
```

已完成本地手动联调：

- `/history` 可以展示 AI 历史列表。
- AI 历史列表可以覆盖简历诊断、目标岗位解析、匹配分析、岗位优化建议和局部改写。
- 可以查看 AI 结果详情。
- 可以按结果类型、状态、简历 ID 和目标岗位 ID 筛选。
- 无历史记录、失败状态和无权限访问有明确提示。
- 前端不展示 API Key、完整 Prompt 等敏感信息。

## 当前不足

- 前端详情 `content` 当前采用通用结构化展示，后续可按 `resultType` 做更细的专用排版。
- 当前未引入统一 AI 结果流水表；如后续需要审计、统计或评估闭环，可再评估是否新增。
- v2.6 只做历史回看，不做 AI 输出质量评估；评估流程进入 v2.7。

## 结果

v2.6 已完成 AI 结果持久化与历史回看闭环。当前系统可以统一查询和回看简历诊断、目标岗位解析、匹配分析、岗位优化建议和局部改写结果，并支持前端列表筛选、详情查看和业务跳转，同时保持不新增 AI 生成能力和不暴露敏感信息的边界。

下一步进入 v2.7，建立 AI 输出评估流程。
