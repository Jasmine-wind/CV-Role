# v3.5 解析与 AI 任务状态机落地

## 目标

在 v3.4 异步任务基础设施之上，选择首批高价值长耗时任务接入“提交任务 -> 后台执行 -> 查询状态 -> 成功展示结果 / 失败展示原因”的闭环。

## 完成内容

| 小任务 | 状态 | 说明 |
|---|---|---|
| v3.5.1 选择首批异步化任务 | 已完成 | 已确认首批改造 `RESUME_PARSE`、`RESUME_DIAGNOSIS`、`RESUME_EMBEDDING` |
| v3.5.2 简历解析任务状态化 | 已完成 | 已新增解析异步提交接口和后台 worker |
| v3.5.3 AI 分析任务状态化 | 已完成 | 已将简历诊断接入任务状态机 |
| v3.5.4 向量生成任务状态化 | 已完成 | 已将简历向量生成接入任务状态机 |
| v3.5.5 前端任务状态展示 | 已完成 | `/resumes` 页面已切换为提交任务后轮询 |
| v3.5.6 v3.5 联调、审查与日志 | 已完成 | 已完成手动验收、验证记录和最终收口 |

## 关键结果

- 首批异步任务收敛为 `RESUME_PARSE`、`RESUME_DIAGNOSIS`、`RESUME_EMBEDDING`。
- 新增 `POST /api/resumes/{id}/parse/tasks`、`POST /api/resumes/{id}/diagnosis/tasks`、`POST /api/resumes/{resumeId}/embeddings/tasks`。
- 新增 `ResumeAsyncTaskService`，通过 `applicationTaskExecutor` 后台执行原解析、诊断和向量生成逻辑。
- 任务成功后继续从原业务查询接口读取完整结果，旧同步接口保留。
- `/resumes` 页面完成异步提交、轮询、平滑进度、成功刷新、失败提示和运行中按钮禁用。
- 向量任务失败原因已透传，未解析、解析未成功、Embedding 配置或服务异常可显示明确原因。

## 验证结果

- 后端异步任务测试通过：`./mvnw test -Dtest=ResumeAsyncTaskServiceImplTest,AsyncTaskServiceImplTest,AsyncTaskFailureHandlerImplTest,AsyncTaskConfigTest`
- 向量任务失败原因测试通过：`./mvnw test -Dtest=ResumeAsyncTaskServiceImplTest,AsyncTaskFailureHandlerImplTest,ResumeEmbeddingServiceImplTest,OpenAiCompatibleEmbeddingClientServiceTest`
- 后端编译通过：`./mvnw test -DskipTests`
- Phase 1 API 集成测试通过：`./mvnw test -Dtest=Phase1ApiIntegrationTest`
- 前端构建通过：`npm run build`
- 手动验收通过：简历解析、简历诊断、简历向量生成均可提交任务并展示状态，失败场景可显示原因。

## 当前不足

- 目标岗位解析、匹配分析、岗位优化建议、岗位向量生成和局部改写仍保留同步流程，等待后续批次评估。
- 当前前端任务状态展示先落在 `/resumes` 页面，尚未抽成全局任务中心。
- 单体内线程池异步任务不支持后端进程重启后的自动恢复，后续如需要可在任务恢复扫描中补齐。

## 结果

v3.5 已完成，进入 v3.6 安全加固与敏感信息治理。
