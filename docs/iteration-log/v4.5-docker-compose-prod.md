# v4.5 - Docker 镜像与 Compose 生产编排

## 目标

把后端、前端、Nginx、PostgreSQL、Redis、MinIO 串成可复现的生产容器编排，形成项目正式部署入口。

## 完成内容

- 新增 `backend/Dockerfile`，后端采用 Java 21 运行环境并通过环境变量读取配置。
- 新增 `web/Dockerfile`，前端采用多阶段构建，构建后由 Nginx 托管静态资源。
- 新增 `deploy/nginx/nginx.conf` 和 `deploy/nginx/conf.d/ai-resume.conf`，统一静态资源服务、`/api` 反向代理和 OpenAPI 调试路径。
- 新增 `docker-compose.prod.yml`，包含 PostgreSQL + pgvector、Redis、MinIO、后端和 Nginx，补齐 volume、restart policy、healthcheck 和服务依赖。
- 新增 `.env.production.example`，集中列出生产环境需要替换的变量。
- 新增 `backend/src/main/resources/logback-spring.xml`，让后端日志可以写入挂载卷。
- 将 v4.5 的状态、任务和验证结果沉淀到 Phase 5 阶段记录。

## 当前不足

- 还没有实际执行 `docker compose -f docker-compose.prod.yml up --build` 做全链路镜像构建。
- 域名、HTTPS 和证书续期留到 v4.6。
- 数据备份与日志巡检留到 v4.7。

## 验证

已执行：

```bash
docker compose -f docker-compose.prod.yml config
ruby -e 'require "yaml"; data = YAML.load_file("docker-compose.prod.yml"); puts data["services"].keys.sort'
```

结果：

- 当前本机 podman rootless 运行目录只读，`docker compose -f docker-compose.prod.yml config` 无法直接完成。
- 已用 Ruby YAML 解析完成结构检查，确认 `services` / `volumes` 及核心服务键存在。
- 生产 Compose 文件已生成，后续可在可用的 Docker / Podman 环境里补跑完整 `compose config` 和 `up --build`。

## 结果

v4.5 已完成生产编排骨架。项目现在具备后端、前端、Nginx、PostgreSQL、Redis、MinIO 的容器化落点，下一步进入服务器部署和 HTTPS 收口。
