# v1.2 统一异常、错误码与参数校验增强

## 1. 本轮目标
增强后端错误处理和参数校验能力，使核心 API 的错误返回更稳定、更可预测，并让前端可以继续基于统一结构展示错误提示。

本轮不引入 Flyway、OpenAPI、CI 或复杂业务功能。

## 2. 本轮完成内容
- 梳理现有 `Result<T>` 统一返回结构
- 新增 `ResultCode` 稳定错误码枚举
- 增强 `Result<T>` 错误响应字段
- 增强 `BusinessException`
- 增强 `GlobalExceptionHandler`
- 统一处理参数校验异常
- 统一处理请求参数类型错误
- 统一处理请求体格式错误
- 统一处理文件上传缺失和 multipart 异常
- 统一处理上传文件过大异常
- 统一处理 `FileStorageException`
- 统一处理 `AiClientException`
- 统一处理无权限异常
- 新增 `JwtAccessDeniedHandler`
- 增强 `JwtAuthenticationEntryPoint`
- 给登录请求补充长度校验
- 给注册请求调整密码长度上限
- 给岗位匹配请求补充正数校验
- 给简历、AI 分析、岗位、岗位匹配和历史记录接口的路径参数补充正数校验
- 给历史记录分页参数补充范围校验
- 更新前端 `ApiResult<T>` 类型，兼容 `path` 和 `timestamp`
- 更新 Phase 2 任务清单，将 v1.2 标记为已完成，下一步切换到 v1.3

## 3. 错误响应结构
错误响应统一使用 `Result<T>`：

```json
{
  "code": 400,
  "message": "请求参数不正确",
  "data": null,
  "path": "/api/example",
  "timestamp": "2026-05-09T18:30:00"
}
```

当前稳定错误码：

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 请求参数不正确 |
| 401 | 未登录或登录已过期 |
| 403 | 无权限访问 |
| 404 | 资源不存在 |
| 413 | 请求体过大 |
| 502 | AI 服务调用失败 |
| 500 | 服务器内部错误 |

## 4. 参数校验范围
- 注册：用户名、邮箱、密码、昵称
- 登录：账号、密码
- 岗位匹配请求：岗位 ID
- 简历相关路径参数：简历 ID
- AI 分析相关路径参数：简历 ID
- 岗位详情路径参数：岗位 ID
- 岗位匹配路径参数：简历 ID
- 历史记录详情路径参数：简历 ID
- 历史记录分页参数：页码和每页数量

## 5. 关键技术点
- `ResultCode` 负责沉淀稳定错误码，避免错误码分散在各处。
- `BusinessException` 继续兼容旧的数字 code 构造方式，降低本轮改动范围。
- `GlobalExceptionHandler` 负责普通 Controller 异常。
- `JwtAuthenticationEntryPoint` 负责 Spring Security 认证失败场景。
- `JwtAccessDeniedHandler` 负责 Spring Security 已认证但无权限场景。
- 前端请求层继续优先读取后端返回的 `message`，同时类型上兼容新增字段。

## 6. 当前不足
- 旧业务代码中仍有直接使用数字 code 创建 `BusinessException` 的地方，后续可逐步替换为 `ResultCode`。
- 当前错误响应尚未加入 traceId，后续 v1.4 日志规范或 requestId 设计时再处理。
- 参数校验已覆盖核心入口，但复杂业务规则仍保留在 Service 层。
- HTTP 状态和业务 code 的完全一致性可在后续接口集成测试中继续收紧。
