# v4.3 - MinIO 正式接入与文件存储切换

## 目标

将 MinIO 从配置预留升级为正式 `FileStorageService` 实现，使简历上传、解析和删除可以在本地存储与 MinIO 之间通过配置切换。

## 完成内容

- 新增 `io.minio:minio` SDK 依赖。
- 新增 `MinioStorageConfig`，在 `app.storage.type=minio` 时创建 `MinioClient`。
- 新增 `MinioFileStorageService`，实现上传对象、读取对象流、删除对象、判断存在、读取元信息和自动创建 bucket。
- 复用 `StoreFileCommand`、`StoredFile`、`StoredFileMetadata`、`SafeFilenameGenerator` 和已有 `FileStorageService` 边界。
- 保留 `LocalFileStorageService`，本地开发仍可使用 `APP_STORAGE_TYPE=local`。
- 生产 Profile 默认优先使用 `APP_STORAGE_TYPE=minio`。
- 更新 `.env.example`，明确 `APP_STORAGE_TYPE=local|minio`，并说明 MinIO bucket 应保持私有，文件访问继续走后端权限校验。
- 新增 `MinioFileStorageServiceTest`，覆盖上传、bucket 创建、元信息读取和非法 objectKey / bizType 拦截。
- 更新 `docs/phase-5-productization-deployment-v4.md` 中 v4.3 的任务状态、实现结果和验证阻塞。
- `git diff --check` 已通过。

## 主流程影响

- 简历上传仍通过 `FileStorageService.store`，切换 MinIO 不改变上传接口。
- 简历解析仍通过 `FileStorageService.loadAsStream`，切换 MinIO 不依赖本地路径。
- 简历删除仍通过 `FileStorageService.delete`，切换 MinIO 后会删除对象存储中的文件。
- 前端不直接接触 MinIO objectKey 或永久公开 URL。

结果：

如需真实 MinIO 验收，再启动本地依赖：

```bash
docker compose up -d minio
```

并设置：

```text
APP_STORAGE_TYPE=minio
MINIO_ENDPOINT=http://localhost:9000
MINIO_ACCESS_KEY=local-minio-user
MINIO_SECRET_KEY=change-me-local-minio-password
MINIO_BUCKET=ai-resume-files
```

## 结果

v4.3 已完成 MinIO 正式接入。简历文件存储可通过 `APP_STORAGE_TYPE=local|minio` 切换，上传、解析和删除继续复用 `FileStorageService` 边界，不改变业务接口。
