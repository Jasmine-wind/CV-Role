# v2.9 - 简历文本解析质量优化

## 目标

提升简历文本提取、清洗、章节识别和结构化解析稳定性，减少解析错误对简历诊断、岗位匹配、优化建议、局部改写、Embedding 和 RAG 的连锁影响。

边界：不做 OCR，不做模型微调，不新增岗位匹配、简历诊断、优化建议或局部改写主流程能力。

## 完成内容

### 解析基础链路

- 新增文本质量检查，覆盖空文本、文本过短、疑似扫描版 PDF、异常字符比例和换行异常。
- 新增清洗文本与章节识别结果保存，解析流程改为使用清洗文本进入基础结构化解析。
- 基础结构化解析按章节提取 basicInfo、education、skills、projects、workExperiences、internships、campusExperiences、awards、certificates、summary 和 others。
- 新增解析质量校验，输出 `GOOD` / `WARNING` / `FAILED`、质量分数、警告和提示。

### DOCX 与复杂模板

- DOCX 提取支持普通段落、表格、页眉、页脚、文本框 / shape 文本。
- 清洗层支持行级 normalize 去重、页脚过滤、编号清理、CJK compatibility 字符窄归一化和内容前置挂载。
- 章节识别扩展中文、英文、中英混合和近义标题，减少技能、教育、项目、经历和 summary 串行污染。
- 针对复杂 DOCX 样例完成文本块顺序修复、业务展示顺序重排和前端折叠调试展示。

### AI 解析辅助

- 新增 AI 辅助章节归类：以 blocks 为输入，只要求输出 `index`、`section`、`confidence`。
- AI 章节归类支持失败降级、分批、耗时记录、内存缓存和 Prompt 精简。
- 新增 AI 结构化补全与 Schema 校验；AI 输出失败、超时、JSON 不合法或校验失败时回退规则结果。
- v2.9.17 后 AI 状态明确区分 `USED`、`SKIPPED`、`FALLBACK`、`DISABLED`；AI 未调用不再显示为降级，缓存只服务真实 AI 调用。

### 结构解耦

- `structuredResult` 新增 `parseMeta`、`rawSections`、`structuredData`，同时保留旧字段兼容。
- `rawSections` 保留原始章节结构、标题、标准化章节、置信度、来源、顺序和 blocks。
- `structuredData` 服务后续分析：skills 改为标签集合，experiences 统一工作 / 实习 / 校园 / 实践经历，projects 支持 `parentExperienceIndex`，achievements 替代 awards。
- 前端主视图优先读取 `structuredData`，`rawSections` 和调试信息默认折叠。

### v2.9.18 样例增强

- 支持图标字体字符清洗和语义映射：邮箱、电话、LinkedIn、GitHub、教育、经历、技能、获奖、其他信息。
- 支持顶部“基础信息 + 右侧技能”混排行拆分，避免姓名、邮箱、电话、GitHub 与技能互相污染。
- basicInfo 增强 GitHub、学校城市、专业、毕业时间、GPA、CET/语言能力和排名抽取。
- 技能词典补充 Python、C++、C、Verilog、Linux、OpenCV、YOLO、DETR、Transformer、PyTorch、TensorFlow、Scikit-learn、Pandas、MATLAB。
- SRTP 复合章节优先归入项目，提取 role、mentor、timeRange、techStack 和 responsibilities。
- 获奖行支持“等级, 竞赛名称 时间”和“前 20%, CCF...”格式。

### AI 展示优化

- 新增 `displayModel`、`aiDisplayModel`、`ruleDisplayModel`；当前主链路先同步生成 `ruleDisplayModel`，有可用缓存时再展示 `aiDisplayModel`，不修改 `structuredData` 原始事实。
- AI 展示优化只接收 basicInfo、structuredData、rawSections 摘要、parseMeta 和 qualityWarnings，不传 rawText、blocks 或 debug 全量。
- AI 展示模型支持缓存，缓存 key 覆盖 resumeId、structuredDataHash、displayPromptVersion、modelName 和 displayAdapterVersion。
- AI 输出经过事实校验，不能新增输入中不存在的公司、学校、职位、项目、技能、时间或奖项；失败时降级为规则 displayModel。
- 前端主视图优先渲染 displayModel，旧数据缺少 displayModel 时继续使用规则 adapter；structuredData、rawSections 和 blocks 默认作为调试信息折叠。
- v2.9.19 后展示生成改为规则先聚合卡片，AI 仅缓存命中或后续可选润色，不再阻塞 FAST 模式。

### v2.9.19 Indexed Line Pointer

- 新增 `indexedLines`：对 `rawSections.blocks` 按展示顺序生成连续 `lineId`，保留 `text`、`normalizedText`、`rawSectionId`、`sectionHint`、置信度、来源类型和噪声标记。
- 新增 `sourceRef`：education、experiences、projects、achievements、summary 关联原文行号范围和原文片段，前端默认展示摘要，展开后查看 `sourceRef.text`。
- 新增 `ResumeLineIndexer`、`ResumePointerValidator`、`ResumePointerPostProcessor`，保证 sourceText 来自原文行，不由 AI 直接生成长事实文本。
- 新增 `ResumePointerExtractionService` 与分任务 pointer prompt，按 BASIC_INFO / EDUCATION / WORK_EXPERIENCE / PROJECT / ACHIEVEMENT / SUMMARY 返回 lineId / lineRange。
- Pointer extraction 缓存 key 覆盖 resumeId、indexedLinesHash、parseMode、extractorType、promptVersion、modelName 和 parserVersion；FAST 模式不调用 AI pointer extractor。
- Pointer 结果会裁剪非法 lineId、非法 lineRange、字段标签实体行和越界置信度，缓存返回使用对象拷贝，避免命中缓存污染上一次返回状态。
- 本次不做 OCR、不做模型微调，不修改简历诊断、岗位匹配、优化建议或局部改写主流程。

## 当前不足

- 不做 OCR，扫描版 PDF 或图片型简历仍无法修复文本缺失。
- 不做视觉坐标还原，多栏 PDF/DOCX 只能通过文本顺序、章节语义和业务顺序缓解错位。
- 技能抽取仍依赖白名单和别名词典，未覆盖技术词需要按样例继续补充。
- `structuredData` 仍主要由规则和兼容层派生，不等同于完整语义理解。
- AI 展示优化只整理展示模型，不修正解析事实；如果上游 structuredData 缺失，展示模型只能降级为待确认内容或规则摘要。
- Pointer extraction 服务已具备分任务 prompt、校验和缓存，但主解析链路仍优先用规则聚合与 sourceRef 兜底，后续可按样例逐步扩大 BALANCED / ACCURATE 的 pointer 调用范围。
- 用户手动修正只完成方案和前端确认状态，尚未实现编辑保存和下游 AI 结果重算。
- 解析评估集仍是轻量人工基线，尚未接入自动化评测脚本。
- AI 章节归类缓存为进程内缓存，后端重启后会清空。
