# v2.8 - Embedding / pgvector / RAG 初步增强

## 目标

建立基础语义匹配和轻量检索增强能力，为后续简历与岗位描述的语义相似度分析打基础。

v2.8 只负责基础向量化、基础语义相似度查询和简单 RAG 检索增强，不做复杂推荐系统、企业级知识库、多轮对话、职业顾问聊天、模型微调或微服务拆分。

## 完成内容

- 检查当前本地 PostgreSQL 客户端版本：`psql 16.13`。
- 检查当前 Compose PostgreSQL 镜像：`postgres:16-alpine`。
- 启动本地 PostgreSQL 容器 `ai-resume-optimizer-postgres`。
- 确认容器内 PostgreSQL 版本为 16.13。
- 通过 `pg_available_extensions` 检查当前镜像中未提供 `vector` 扩展。
- 通过 `pg_extension` 检查当前数据库未启用 `vector` 扩展。
- 执行 `CREATE EXTENSION IF NOT EXISTS vector;` 验证失败，错误原因为当前镜像缺少 `vector.control`。
- 明确当前本地数据库不能直接使用 pgvector。
- 明确后续需要切换到带 pgvector 的 PostgreSQL 16 镜像后，再通过 Flyway 初始化 `CREATE EXTENSION IF NOT EXISTS vector;`。
- 明确向量维度不能从当前聊天模型推断，应由后续实际接入的 Embedding 模型决定。
- 明确 pgvector 不可用时的临时降级策略：开发过渡期可以保存 Embedding JSON 字符串，但不能作为最终方案。
- 更新 `README.md`，记录 pgvector 本地环境结论和后续接入边界。
- 将 `docker-compose.yml` 中 PostgreSQL 镜像从 `postgres:16-alpine` 调整为 `pgvector/pgvector:pg16`。
- 新增 `backend/src/main/resources/db/migration/V12__enable_pgvector_extension.sql`，通过 Flyway 初始化 `vector` 扩展。
- 新增 `backend/src/main/resources/db/migration/V13__create_embedding_tables.sql`，创建 `resume_embeddings` 和 `job_description_embeddings`。
- `resume_embeddings` 关联 `resumes.id` 和 `users.id`，记录简历文本片段、向量、模型、维度、状态、错误信息和时间字段。
- `job_description_embeddings` 关联 `job_descriptions.id` 和 `users.id`，记录岗位描述文本片段、向量、模型、维度、状态、错误信息和时间字段。
- 向量字段使用不固定维度的 `vector` 类型，实际维度通过 `embedding_dimension` 追踪，避免在 Embedding 模型确定前硬编码维度。
- 当前只建立业务查询索引，不建立 HNSW / IVFFlat 等向量近似索引；向量索引留到模型维度和查询策略确定后再补。
- 新增 `ResumeEmbedding`、`JobDescriptionEmbedding` 实体。
- 新增 `ResumeEmbeddingMapper`、`JobDescriptionEmbeddingMapper`，供 MyBatis-Plus 扫描。
- 新增 `EmbeddingClientService` 接口，作为业务层后续调用 Embedding 能力的统一入口。
- 新增 `EmbeddingClientProperties`，通过 `app.ai.embedding-compatible` 管理 Embedding API Key、base-url、模型名称、向量维度、超时和最大输入长度。
- 新增 `OpenAiCompatibleEmbeddingClientService`，调用 OpenAI-compatible `/embeddings` 接口将文本转换为向量。
- Embedding 客户端支持空文本校验、文本长度校验、HTTP 失败处理、IO 失败处理、超时处理、中断处理、响应向量解析和维度一致性校验。
- 在 `application.yaml`、`.env.example` 和 `README.md` 中补充 `EMBEDDING_*` 配置示例。
- 新增 `OpenAiCompatibleEmbeddingClientServiceTest`，覆盖响应解析、空文本、过长文本和维度不一致。
- 完成 v2.8.3 Embedding 模型与环境配置确认：默认模型为 `Qwen3-Embedding-0.6B`，默认维度为 `1024`。
- `EMBEDDING_BASE_URL` 保持由实际 OpenAI-compatible Embedding 服务地址配置，不绑定具体服务商。
- 当前不使用 Qwen3-Embedding-4B、Qwen3-Embedding-8B，不引入 Reranker。
- v2.8.3 Embedding 配置结论和下一步边界已合并进 `docs/tasks/phase-3-task-list.md`。
- 新增 `TextChunkService` 和 `TextChunkServiceImpl`，用于将简历结构化解析结果和原始解析文本切成 Embedding 文本片段。
- 当前简历切分策略为轻量段落切分：优先包含结构化解析 JSON，再按原始解析文本段落切分；单片段最大 1200 字符，最多 8 个片段。
- 新增 `ResumeEmbeddingService` 和 `ResumeEmbeddingServiceImpl`，实现简历向量生成主流程。
- 新增 `ResumeEmbeddingController`，提供 `POST /api/resumes/{resumeId}/embeddings` 和 `GET /api/resumes/{resumeId}/embeddings`。
- 新增 `ResumeEmbeddingSummaryVO` 和 `ResumeEmbeddingRecordVO`。
- 生成简历向量前校验当前用户拥有该简历，且简历解析状态必须为 `SUCCESS`。
- 重复生成策略为覆盖式生成：先删除同一简历旧向量，再基于当前解析结果重新生成。
- 每个文本片段先写入 `PENDING` 记录，再调用 Embedding 服务；成功后写入 pgvector 向量、模型名称、维度和 `SUCCESS` 状态，失败后写入 `FAILED` 状态和错误信息。
- `ResumeEmbeddingMapper` 增加 pgvector 专用更新方法，通过 `CAST(#{embedding} AS vector)` 写入向量字段。
- 简历删除链路已同步删除 `resume_embeddings`，避免外键约束影响删除。
- 新增 `TextChunkServiceImplTest` 和 `ResumeEmbeddingServiceImplTest`，并更新 `ResumeServiceImplTest`。
- `TextChunkService` 新增岗位描述文本切片入口，优先包含结构化解析内容，再按原始岗位描述段落切分。
- 新增 `JobDescriptionEmbeddingService` 和 `JobDescriptionEmbeddingServiceImpl`，实现岗位描述向量生成主流程。
- 新增 `JobDescriptionEmbeddingController`，提供 `POST /api/job-descriptions/{jobDescriptionId}/embeddings` 和 `GET /api/job-descriptions/{jobDescriptionId}/embeddings`。
- 新增 `JobDescriptionEmbeddingSummaryVO` 和 `JobDescriptionEmbeddingRecordVO`。
- 生成岗位描述向量前校验当前用户拥有该岗位描述，且岗位描述解析状态必须为 `SUCCESS`。
- 岗位描述向量重复生成策略为覆盖式生成：先删除同一岗位描述旧向量，再基于当前解析结果重新生成。
- 每个岗位描述文本片段先写入 `PENDING` 记录，再调用 Embedding 服务；成功后写入 pgvector 向量、模型名称、维度和 `SUCCESS` 状态，失败后写入 `FAILED` 状态和错误信息。
- `JobDescriptionEmbeddingMapper` 增加 pgvector 专用更新方法，通过 `CAST(#{embedding} AS vector)` 写入向量字段。
- 岗位描述删除链路已同步删除 `job_description_embeddings`，避免外键约束影响删除。
- 新增 `JobDescriptionEmbeddingServiceImplTest`，并更新 `TextChunkServiceImplTest` 和 `JobDescriptionServiceImplTest`。
- 新增 `SemanticMatchService` 和 `SemanticMatchServiceImpl`，实现简历向量与岗位描述向量的基础语义相似度查询。
- 新增 `SemanticMatchController`，提供 `GET /api/resumes/{resumeId}/semantic-matches`。
- 查询参数支持 `jobDescriptionId` 和可选 `topK`，`topK` 默认 5，最大限制为 20。
- 基础相似度查询使用 pgvector 余弦距离操作符 `<=>`，相似度分数按 `1 - distance` 计算，并限制在 0 到 1。
- 新增 `SemanticMatchResultVO` 和 `SemanticMatchItemVO`，返回整体相似度、Top-K 相似片段、简历片段、岗位描述片段和相似度分数。
- 新增 `SemanticMatchRow`，承接 MyBatis 查询结果。
- `ResumeEmbeddingMapper` 增加 `selectTopSemanticMatches`，基于 `resume_embeddings` 与 `job_description_embeddings` 的成功向量做相似度排序。
- 语义相似度查询前会校验当前用户拥有简历和岗位描述。
- 语义相似度查询前会校验简历向量和岗位描述向量均已生成成功。
- 语义相似度查询前会校验简历向量与岗位描述向量维度一致。
- 新增 `SemanticMatchServiceImplTest`，覆盖成功查询、Top-K 限制、缺少简历向量和维度不一致。
- 新增 `ResumeRagService` 和 `ResumeRagServiceImpl`，基于语义相似度结果组装简单 RAG 上下文。
- 新增 `RagContextDTO`，记录是否使用 RAG、匹配片段数量、上下文文本和说明。
- RAG 默认取 Top-3 语义相似片段，最大上下文长度限制为 1800 字符。
- RAG 上下文格式包含简历片段、岗位描述片段、相似度分数和辅助原因。
- RAG 上下文只来自当前用户自己的简历和岗位描述向量结果，不接入外部知识库。
- 无简历向量、无岗位描述向量、无相似片段或维度不一致时，RAG 返回未使用说明，不阻断原有 AI 匹配和优化建议流程。
- 权限或资源不存在类错误仍继续抛出，不被 RAG 降级吞掉。
- `AiJobMatchPromptService` 和 `AiResumeSuggestionPromptService` 已增加可选 RAG 上下文参数，并保留原 3 参数调用入口。
- AI 匹配 Prompt 和 AI 优化建议 Prompt 已加入“语义检索辅助上下文（可选）”段落和使用边界说明。
- `AiJobMatchServiceImpl` 和 `AiResumeSuggestionServiceImpl` 已接入 `ResumeRagService`。
- AI 匹配和优化建议启动日志会记录 `ragUsed` 和 `ragMatchCount`。
- 新增 `ResumeRagServiceImplTest`，并更新 Prompt 与 AI 服务相关测试。
- 已通过接口文档完成 v2.8.8 联调验收：pgvector、Embedding 调用、简历向量、岗位描述向量、语义相似度、Top-K、RAG 接入和异常场景均按预期通过。
- 已确认 AI 岗位匹配接口请求体字段为 `jobDescriptionId`，AI 优化建议接口为 `/api/resumes/{id}/ai-suggestions`。
- 已检查敏感配置边界：真实 API Key 仅保留在本地 `.env`，不写入 `.env.example`、README 或提交文档。

## 验证结果

已执行本地环境检查：

```bash
psql --version
docker compose up -d postgres
docker compose exec -T postgres psql -U dawn -d ai_resume_optimizer -c "select version();"
docker compose exec -T postgres psql -U dawn -d ai_resume_optimizer -c "select name, default_version, installed_version from pg_available_extensions where name = 'vector';"
docker compose exec -T postgres psql -U dawn -d ai_resume_optimizer -c "select extname, extversion from pg_extension where extname = 'vector';"
docker compose exec -T postgres psql -U dawn -d ai_resume_optimizer -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

已通过 Swagger / 接口文档完成业务联调：

- 登录接口使用 `account` + `password` 获取 JWT Token。
- 已生成并查询简历向量。
- 已生成并查询岗位描述向量。
- 已查询简历与岗位描述 Top-K 语义相似片段。
- 已验证 AI 岗位匹配可接入 RAG 上下文，日志记录 `ragUsed` 和 `ragMatchCount`。
- 已验证 AI 简历优化建议可接入 RAG 上下文。
- 已验证无向量、无岗位描述向量、维度不一致、Top-K 限制和越权访问等异常边界按预期处理。

检查结论：

- PostgreSQL 版本满足后续 pgvector 接入的基础版本要求。
- 原 `postgres:16-alpine` 镜像不包含 pgvector 扩展，已切换为 `pgvector/pgvector:pg16`。
- 当前 pgvector 扩展可用，Flyway 可以执行 V12 / V13 迁移。
- 当前 v2.8.1 不新增数据库迁移脚本、不新增向量表、不实现 Embedding 调用、不实现 RAG。
- 当前 v2.8.2 已新增迁移脚本、实体和 Mapper，但未实现 Embedding 调用、语义查询或 RAG。
- 当前 v2.8.3 已新增 Embedding 客户端和配置，未保存向量到数据库，未实现语义查询或 RAG。
- 当前 v2.8.4 已实现简历向量生成和查询接口，未实现岗位描述向量、语义查询或 RAG。
- 当前 v2.8.5 已实现岗位描述向量生成和查询接口，未实现语义查询或 RAG。
- 当前 v2.8.6 已实现基础语义相似度查询，未实现 RAG。
- 当前 v2.8.7 已实现简单 RAG 上下文组装和 Prompt 可选接入。
- 当前 v2.8.8 已完成接口联调、异常场景检查、安全边界检查和文档收口。

## 当前不足

- 当前默认 Embedding 模型为 `Qwen3-Embedding-0.6B`，默认维度为 `1024`，仍可通过 `EMBEDDING_MODEL` 和 `EMBEDDING_DIMENSION` 覆盖。
- 当前 `EMBEDDING_BASE_URL` 仍需要按实际 OpenAI-compatible Embedding 服务地址配置。
- 当前 RAG 只是基于用户自己的简历和岗位描述片段做轻量上下文增强，不包含外部知识库、Reranker、多轮问答或复杂引用体系。
- 当前向量索引仍只保留业务查询索引，未建立 HNSW / IVFFlat 近似向量索引。

## 结果

v2.8.1 已完成 pgvector 可行性检查。当前环境的 PostgreSQL 版本可作为后续基础，但原有镜像不支持 pgvector。

v2.8.2 已完成向量表设计和基础落地：Compose 已切换到 pgvector 镜像，Flyway 已准备扩展初始化和两张向量表迁移，后端已新增实体和 Mapper。

v2.8.3 已完成 Embedding 客户端接入：后端具备通过 OpenAI-compatible `/embeddings` 接口获取向量的基础能力，并能校验配置维度和处理常见错误。当前尚未实现向量保存、语义查询或 RAG。

v2.8.4 已完成简历向量生成：系统可以基于已成功解析的简历生成文本片段，调用 Embedding 服务生成向量，并保存到 `resume_embeddings` 表。当前未实现岗位描述向量、语义查询或 RAG。

v2.8.5 已完成岗位描述向量生成：系统可以基于已成功解析的岗位描述生成文本片段，调用 Embedding 服务生成向量，并保存到 `job_description_embeddings` 表。当前未实现语义查询或 RAG。

v2.8.6 已完成基础语义相似度查询：系统可以基于已生成的简历向量和岗位描述向量返回 Top-K 相似片段，结果包含简历片段、岗位描述片段和相似度分数。当前未实现 RAG。

v2.8.7 已完成简单 RAG 检索增强：系统可以基于语义相似度结果组装受长度限制的 RAG 上下文，并可选接入 AI 匹配和 AI 优化建议 Prompt。没有可用片段时不会阻断原有流程。

v2.8.8 已完成 v2.8 联调、审查与日志收口：用户已通过接口文档完成登录、向量生成、语义相似度查询、RAG 接入 AI 匹配与优化建议、异常边界和安全检查。

v2.8 已完成。下一步 Phase 3 AI 能力增强阶段结束，可进入 Phase 4，或先整理项目演示、简历描述和面试讲解材料。
