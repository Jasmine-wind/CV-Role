# v2.8 - Embedding / pgvector / RAG 初步增强

## 目标

建立基础语义匹配和轻量检索增强能力，为后续“简历内容 + 岗位描述”的语义相似度分析和 Prompt 上下文增强打基础。

v2.8 只负责 pgvector 基础环境、Embedding 客户端、简历 / 岗位描述向量生成、基础语义相似度查询和简单 RAG 上下文接入，不做复杂推荐系统、企业级知识库、多轮对话、Reranker、模型微调或微服务拆分。

## 完成内容

- 已完成本地 PostgreSQL 与 pgvector 可行性检查，确认原 `postgres:16-alpine` 镜像不包含 `vector` 扩展。
- 已将 `docker-compose.yml` 中 PostgreSQL 镜像切换为 `pgvector/pgvector:pg16`。
- 已新增 Flyway 迁移 `V12__enable_pgvector_extension.sql` 和 `V13__create_embedding_tables.sql`，初始化 `vector` 扩展并创建 `resume_embeddings`、`job_description_embeddings`。
- 已新增简历向量和岗位描述向量实体、Mapper、VO 和业务服务。
- 已新增 OpenAI-compatible Embedding 客户端，支持配置校验、文本长度限制、HTTP / IO / 超时错误处理、响应向量解析和维度一致性校验。
- 已确认当前默认 Embedding 模型为 `Qwen/Qwen3-Embedding-0.6B`，默认维度为 `1024`，并通过 `EMBEDDING_*` 环境变量配置。
- 已新增 `TextChunkService`，将简历结构化结果、简历原文、岗位描述结构化结果和岗位描述原文切分为有限文本片段。
- 已实现 `POST /api/resumes/{resumeId}/embeddings`、`GET /api/resumes/{resumeId}/embeddings`。
- 已实现 `POST /api/job-descriptions/{jobDescriptionId}/embeddings`、`GET /api/job-descriptions/{jobDescriptionId}/embeddings`。
- 已在生成向量前校验当前用户资源权限，以及简历 / 岗位描述解析状态必须为 `SUCCESS`。
- 已采用覆盖式重复生成策略，重新生成前删除同一资源旧向量。
- 已在简历删除和岗位描述删除链路中同步清理向量记录。
- 已新增基础语义相似度查询 `GET /api/resumes/{resumeId}/semantic-matches`，支持 `jobDescriptionId` 和 `topK`。
- 已通过 pgvector 余弦距离 `<=>` 查询 Top-K 相似片段，并返回整体相似度、简历片段、岗位描述片段和相似度分数。
- 已新增 `ResumeRagService`，基于 Top-K 语义相似片段组装受长度限制的简单 RAG 上下文。
- 已将 RAG 上下文可选接入 AI 岗位匹配 Prompt 和 AI 简历优化建议 Prompt。
- 无向量、无相似片段或维度不一致时，RAG 返回未使用说明，不阻断原有 AI 匹配和优化建议流程。
- 已完成接口文档联调，覆盖登录、简历向量生成、岗位描述向量生成、语义相似度查询、RAG 接入 AI 匹配 / 优化建议和异常边界。
- 已检查敏感配置边界，真实 API Key 只保留在本地 `.env`，不写入 `.env.example`、README 或提交文档。
- 已完成 v2.8 任务清单压缩，将 `docs/tasks/phase-3-task-list.md` 中 v2.8 收口为总结和小任务完成情况表。

## 验证结果

已执行本地环境检查：

```bash
psql --version
docker compose up -d postgres
docker compose exec -T postgres psql -U dawn -d ai_resume_optimizer -c "select version();"
docker compose exec -T postgres psql -U dawn -d ai_resume_optimizer -c "select name, default_version, installed_version from pg_available_extensions where name = 'vector';"
docker compose exec -T postgres psql -U dawn -d ai_resume_optimizer -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

已通过接口文档完成业务联调：

- 登录接口使用 `account` + `password` 获取 JWT Token。
- 简历向量生成和查询通过。
- 岗位描述向量生成和查询通过。
- 简历与岗位描述 Top-K 语义相似片段查询通过。
- AI 岗位匹配和 AI 简历优化建议可接入 RAG 上下文，日志记录 `ragUsed` 和 `ragMatchCount`。
- 无向量、无岗位描述向量、维度不一致、Top-K 限制和越权访问等异常边界按预期处理。

## 当前不足

- 当前默认 Embedding 模型为 `Qwen/Qwen3-Embedding-0.6B`，默认维度为 `1024`，后续仍可通过 `EMBEDDING_MODEL` 和 `EMBEDDING_DIMENSION` 覆盖。
- 当前 `EMBEDDING_BASE_URL` 默认指向 `https://api.siliconflow.cn/v1`，客户端内部拼接 `/embeddings`。
- 当前 RAG 只基于用户自己的简历和岗位描述片段做轻量上下文增强，不包含外部知识库、Reranker、多轮问答或复杂引用体系。
- 当前向量索引仍只保留业务查询索引，未建立 HNSW / IVFFlat 近似向量索引。

## 结果

v2.8 已完成 Embedding / pgvector / RAG 初步增强闭环。系统现在可以生成简历和岗位描述向量，查询 Top-K 语义相似片段，并将简单 RAG 上下文可选接入 AI 岗位匹配和 AI 简历优化建议。

下一步进入 v2.9，补强简历文本提取和结构化解析质量。
