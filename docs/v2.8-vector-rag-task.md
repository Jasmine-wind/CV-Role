# v2.8 - Embedding / pgvector / RAG 初步增强

状态：当前版本

## v2.8 目标

在 AI 输出结构和评估流程稳定后，尝试引入基础语义匹配或检索增强能力，为后续更高级 AI 能力打基础。

v2.8 只负责“基础向量化、基础语义相似度查询、简单 RAG 检索增强”，不负责复杂推荐系统、不负责企业级知识库、不负责多轮对话和微服务拆分。

v2.8 完成后应满足：

- 系统可以接入 Embedding 模型。
- 系统可以为简历文本生成向量。
- 系统可以为岗位描述生成向量。
- 系统可以将向量保存到 PostgreSQL + pgvector。
- 系统可以计算简历与岗位描述之间的基础语义相似度。
- 语义相似度结果可以辅助岗位匹配分析。
- 系统可以基于简历片段进行简单检索增强。
- RAG 只作为辅助上下文，不替代原有 AI 匹配和优化建议流程。
- 用户只能检索和使用自己的简历、岗位描述和向量数据。
- 本轮结果记录到 `docs/iteration-log/v2.8-vector-rag.md`。

说明：

- v2.8 不做复杂推荐系统。
- v2.8 不做大规模向量数据库平台。
- v2.8 不做企业级知识库。
- v2.8 不做多轮对话。
- v2.8 不做职业顾问聊天。
- v2.8 不做自动职位投递。
- v2.8 不做模型微调。
- v2.8 不做微服务拆分。
- v2.8 的重点是建立“可运行、可解释、可扩展”的基础语义匹配能力。

## v2.8.4 简历向量生成

状态：未开始

- 调用 Embedding 服务生成简历向量。
- 将简历向量保存到 `resume_embeddings` 表。

任务：

- [ ] 创建简历文本切分服务。
- [ ] 从简历解析结果中读取 `raw_text` 或 `structured_content`。
- [ ] 明确切分策略。
- [ ] 生成文本片段 `chunk_text`。
- [ ] 为每个片段生成 `chunk_index`。
- [ ] 调用 Embedding 服务生成向量。
- [ ] 保存向量到 `resume_embeddings` 表。
- [ ] 保存模型名称和向量维度。
- [ ] 保存生成状态。
- [ ] 处理空文本情况。
- [ ] 处理 Embedding 调用失败。
- [ ] 明确重复生成策略。
- [ ] 实现 `POST /api/resumes/{resumeId}/embeddings`。
- [ ] 实现 `GET /api/resumes/{resumeId}/embeddings`。

建议切分策略：

- Phase 3 先采用简单段落切分。
- 每个片段长度控制在模型允许范围内。
- 优先按项目经历、技能、实习经历、教育经历等结构化字段切分。
- 如果结构化字段不足，可以按原始文本段落切分。

重复生成策略：

- Phase 3 默认覆盖同一简历旧向量。
- 重新生成时先删除旧向量，再写入新向量。
- 如果生成失败，应记录失败状态和错误信息。

建议 API：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/resumes/{resumeId}/embeddings` | 生成简历向量 |
| GET | `/api/resumes/{resumeId}/embeddings` | 查询简历向量生成状态 |

验收标准：

- 已解析简历可以生成向量。
- 未解析简历不能直接生成向量。
- 用户不能为他人的简历生成向量。
- 向量可以保存到数据库。
- 模型名称和向量维度可以追踪。
- 生成失败时记录错误信息。
- 重复生成策略明确。
- 本任务不实现岗位描述向量。
