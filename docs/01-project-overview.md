# AI 简历优化与岗位匹配系统

## 项目总开发文档

---


## 1. 项目概述

### 1.1 项目名称

AI 简历优化与岗位匹配系统

### 1.2 项目背景

对于大学生、应届生和实习求职者而言，简历往往存在表达不精准、项目描述不突出、岗位针对性不足等问题。同时，很多用户并不清楚目标岗位真正需要哪些技能，也缺乏根据岗位要求优化简历的能力。因此，需要一个能够结合简历内容、岗位需求和 AI 能力，帮助用户分析、匹配和优化求职材料的系统。

### 1.3 项目目标

构建一个面向求职场景的 Web 系统，使用户上传简历后，系统能够自动完成简历解析、AI 分析、岗位匹配，并输出可执行的优化建议，后续支持生成针对岗位的定制版简历，逐步演进为具备语义匹配和职业顾问能力的 AI 求职辅助平台。

### 1.4 项目定位

* 面向大学生、应届生、实习生、校招用户
* 以 Web 端为主要交付形式
* 前期聚焦单体项目闭环
* 后期逐步加入工程化、AI 深化、架构升级能力

### 1.5 项目核心价值

* 帮助用户快速识别简历问题
* 提升岗位匹配效率
* 提供可执行的简历优化建议
* 形成具备展示价值的 AI + Java 项目
* 为后续扩展职业规划、岗位推荐、对话式求职助手提供基础

---

## 2. 总体建设原则

### 2.1 单体优先，逐步增强

先完成单体可运行版本，再逐步加入工程化能力、AI 语义能力和架构升级。

### 2.2 先业务闭环，再技术扩展

先解决“注册、上传、解析、分析、匹配、建议”主流程，再逐步增强技术深度。

### 2.3 每个阶段都能独立运行

每个阶段都必须形成可演示版本，并可以作为简历中的一个独立项目版本进行讲解。

### 2.4 技术引入遵循必要性原则

不做过早架构设计，每项技术的引入都必须有明确业务价值和阶段价值。

## 4. 四阶段开发规划

# Phase 1：基础可运行 MVP 阶段

## 4.1 阶段目标

完成项目最核心的业务闭环，做出一个可运行的前后端分离单体系统。用户能够完成登录、上传简历、查看解析结果、获取 AI 分析结果、查看岗位匹配与优化建议。

## 4.2 阶段定位

这是项目的第一版，也是最重要的一版，目标不是做复杂，而是打通主流程，验证产品成立。

* Spring Security + JWT
* MyBatis-Plus

* MinIO

### 前端

* Vue 3
* TypeScript

* Pinia

* Element Plus
* Axios

### 工程与运行

* Maven
* Git
* Docker

## 4.4 本阶段 MVP 功能范围

* 用户注册/登录
* JWT 鉴权
* 简历上传
* 简历文件存储
* 简历文本提取

* 复杂数据统计

## 4.6 阶段产出目标

## 5. 四阶段关系说明

四个阶段之间不是彼此独立重做，而是逐步演进关系：

* Phase 1 解决“业务是否成立、主流程是否跑通”
* Phase 2 解决“项目是否规范、是否具备工程质量”
* Phase 3 解决“AI 是否真正形成差异化能力”
* Phase 4 解决“系统是否具备更强架构与部署能力”

因此，整体开发顺序必须严格遵循：

**Phase 1 → Phase 2 → Phase 3 → Phase 4**

不建议跳阶段开发。

## 7. 项目整体风险与控制策略

### 7.1 风险一：前期技术栈过多导致项目推进困难

控制策略：严格按阶段引入技术，不在 MVP 阶段加入非必要中间件和复杂架构。

### 7.2 风险二：简历解析难度高于预期

控制策略：先实现稳定文本提取与基础结构化，再逐步提升解析质量，不追求一步到位。

### 7.3 风险三：AI 输出不稳定

控制策略：限制输出格式、增加 JSON 结构约束、设置兜底逻辑、保留人工规则匹配。

### 7.4 风险四：岗位匹配难以解释

控制策略：Phase 1 先做规则匹配，Phase 3 再升级为语义匹配，确保每个阶段都可解释。

### 7.5 风险五：文档缺失导致后续混乱

控制策略：每阶段开始前先写阶段开发文档，每轮结束写迭代日志。
