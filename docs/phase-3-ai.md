# Phase 3 - AI 能力增强阶段

## 当前状态

Phase 1 已完成基础可运行 MVP，主流程已经跑通。

Phase 2 目标是工程化增强，包括配置分离、异常处理、数据库迁移、日志、测试、接口文档、本地编排和 CI。

Phase 3 建议在 Phase 2 基本完成后进入。此阶段重点不是继续堆普通 CRUD，而是把项目从“带 AI 调用的简历系统”升级为“真正具备 AI 分析、匹配、改写和评估能力的简历优化系统”。

当前建议从：

```text
v2.1 - AI 能力基线检查与提示词规范
```

开始推进。

---

## 1. 阶段目标

Phase 3 的目标是在基础简历工作流稳定之后，增强系统的 AI 能力，使系统能够围绕“简历内容 + 用户粘贴的目标岗位 JD”完成更深入的分析、匹配和优化。

本阶段完成后，系统应具备以下能力：

- 用户可以提交目标岗位 JD，也可以选择系统预置岗位样例作为参考。
- 系统可以从目标岗位 JD 中抽取结构化岗位要求。
- 系统可以将简历内容与岗位要求进行匹配分析。
- 系统可以输出结构化匹配反馈。
- 系统可以生成有依据的简历优化建议。
- 系统可以生成局部改写建议，而不是直接编造完整经历。
- 系统可以保存 AI 输出结果，便于用户回看。
- 系统可以记录提示词版本和模型元数据。
- 系统具备基础 AI 输出质量评估流程。
- 系统为后续 RAG、向量检索、多轮对话和职业顾问能力预留扩展空间。

---

## 2. 阶段定位

Phase 3 是项目从“基础 AI 调用”升级为“AI 应用能力”的阶段。

Phase 1 的重点是：

```text
业务闭环跑通
```

Phase 2 的重点是：

```text
工程质量增强
```

Phase 3 的重点是：

```text
AI 分析质量、AI 输出可控性、AI 结果可解释性、AI 功能可评估性
```

本阶段不追求炫技式 AI，而是强调：

- 输出基于用户已有简历内容。
- 不编造不存在的经历。
- 建议具体、可审阅、可修改。
- 匹配结果结构化、可保存、可复查。
- 每个 AI 功能都有明确输入、输出和验收标准。

## 5. AI 安全规则

所有 AI 功能必须遵守以下规则：

1. 不编造用户不存在的教育经历、工作经历、项目经历、技能、证书、奖项或量化指标。
2. 区分“事实抽取”和“表达优化”。
3. 改写建议只能基于用户已有内容进行表达优化。
4. 如果简历缺少某项能力，只能建议用户补充学习或补充真实经历，不能直接生成虚假经历。
5. 用户保留最终简历修改权。
6. AI 输出必须尽量结构化，不能让前端依赖完全自由文本。
7. 关键 AI 输出必须保存模型名称、提示词版本和生成时间。
8. AI 输出解析失败时，不得保存脏数据。
9. AI 调用失败时，应返回明确错误信息，不影响系统主流程。
10. 涉及简历原文和个人信息时，日志中不得完整打印敏感内容。

## 6. AI 输出评估原则

每个 AI 功能扩展前，都应定义小型评估集。

评估维度包括：

| 维度 | 说明 |
|---|---|
| 相关性 | 输出是否围绕用户简历和目标岗位 |
| 事实一致性 | 是否没有编造不存在的经历 |
| 具体程度 | 建议是否具体可操作 |
| 实用性 | 是否能帮助用户优化简历 |
| 结构稳定性 | 输出是否符合系统约定 JSON 结构 |
| 可解释性 | 匹配结论是否能说明依据 |
| 安全性 | 是否避免敏感或虚假内容 |

评估方式：

- 准备少量样例简历。
- 准备少量样例目标岗位 JD。
- 固定 Prompt 版本。
- 比较不同输出的质量。
- 记录典型问题。
- 迭代 Prompt 或解析策略。

## 7. 总体排期

建议 Phase 3 拆分为 8 个迭代版本。每个版本形成一个可运行、可验证的 AI 能力增强点。

| 迭代 | 主题 | 核心产出 |
|---|---|---|
| v2.1 | AI 能力基线检查与提示词规范 | 明确 AI 分层、提示词模板和输出约束 |

| v2.3 | 简历与目标岗位匹配分析 | AI 输出结构化匹配反馈 |
| v2.4 | AI 简历优化建议增强 | 生成具体、可审阅、基于事实的优化建议 |
| v2.5 | AI 局部改写建议 | 对项目经历、技能描述等进行局部改写 |
| v2.6 | AI 结果持久化与历史回看 | AI 分析、匹配、改写结果可保存和回看 |
| v2.7 | AI 输出评估流程 | 建立小型评估集和质量检查流程 |
| v2.8 | Embedding / pgvector / RAG 初步增强 | 引入基础语义匹配或检索增强能力 |

### v2.4 - AI 简历优化建议增强

#### 目标

基于 AI 匹配分析结果，生成更具体、更有依据的简历优化建议。

#### 任务拆解

- 设计优化建议结果结构。
- 设计优化建议 Prompt。
- 实现优化建议生成服务。
- 实现优化建议触发接口。
- 实现优化建议查询接口。
- 根据缺失技能生成学习或补充建议。
- 根据弱表达经历生成表达优化建议。
- 根据强匹配项生成突出展示建议。
- 保存优化建议结果。
- 前端展示优化建议。
- 更新 `docs/iteration-log/v2.4-ai-suggestions.md`。

#### 建议输出结构

| 字段 | 说明 |
|---|---|
| type | 建议类型 |
| priority | 优先级 |
| targetSection | 作用于简历哪个部分 |
| issue | 当前问题 |
| suggestion | 修改建议 |
| evidence | 建议依据 |
| caution | 注意事项 |

#### AI 输出要求

- 建议必须引用简历已有内容或岗位要求作为依据。
- 如果用户缺少某项技能，只能建议补充真实学习或经历。

- 建议应区分“可以直接改写”和“需要用户补充真实内容”。

#### 验收标准

- 系统可以基于匹配结果生成优化建议。
- 优化建议具体、可审阅。
- 优化建议有依据。
- 不编造用户不存在的经历。
- 前端可以展示建议类型、优先级和依据。
- 本轮结果记录到 `docs/iteration-log/v2.4-ai-suggestions.md`。

- 可选：基于简历片段做简单 RAG 检索增强。
- 更新 `docs/iteration-log/v2.8-vector-rag.md`。

#### 建议能力边界

- 只做基础语义相似度，不做复杂推荐系统。
- 只做简单 RAG，不做企业级知识库。
- 不做大规模向量数据管理。
- 不做多租户检索系统。

#### 验收标准

- 可以为简历生成 Embedding。
- 可以为目标岗位生成 Embedding。
- 可以计算基础语义相似度。
- 语义匹配结果能辅助岗位匹配分析。
- 不破坏原有关键词匹配和 AI 匹配流程。
- 本轮结果记录到 `docs/iteration-log/v2.8-vector-rag.md`。

## 9. Phase 3 总体验收标准

Phase 3 完成时，应满足：

- 用户可以提交目标岗位 JD。
- 系统可以解析目标岗位。
- 系统可以基于简历和目标岗位生成结构化匹配反馈。
- 系统可以生成具体、有依据的优化建议。
- 系统可以给出局部改写建议。
- AI 输出不会编造用户不存在的经历。
- AI 输出可以持久化和回看。
- AI 输出记录模型名称和 Prompt 版本。
- 至少建立一个基础 AI 输出评估流程。
- 可选：完成基础 Embedding / pgvector / RAG 增强。

## 10. Phase 3 开发顺序

严格按以下顺序推进：

1. v2.1 AI 能力基线检查与提示词规范
2. v2.2 目标岗位输入与结构化解析
