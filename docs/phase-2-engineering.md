# 第二阶段 - 工程化

## 目的

在 MVP 行为存在之后，提升可靠性、可维护性和开发信心。

## 范围

### 范围内

- 集中异常处理。
- 请求和响应校验。
- 数据库迁移策略。
- 服务层测试。
- 关键流程 API 集成测试。
- 日志约定。
- 本地开发和测试环境配置。

### 范围外

- 与 MVP 稳定性无关的大功能扩张。
- 在主要质量问题暴露前进行大规模架构重写。
- AI 专属提示词或模型集成。

## 工程目标

### 校验

输入应当尽早失败，并返回清晰信息。文件上传限制、ID 和用户输入字段需要保持一致校验。

### 错误处理

API 应返回可预测的错误载荷，包含稳定字段，例如错误码、消息和请求路径。

### 持久化

数据库结构变更应可重复执行。当实体和表结构足够稳定时，引入迁移工具。

### 测试

优先覆盖：

- 认证和授权边界。
- 简历上传校验。
- 简历元数据持久化。
- 解析服务行为。

### 可观测性

日志应能帮助定位上传或解析失败，同时避免暴露敏感简历内容。

## 退出标准

- MVP 流程具备有意义的自动化测试。
- 本地和测试配置已经分离。
- 核心 API 错误格式一致。
- 代码库具备清晰包边界。
