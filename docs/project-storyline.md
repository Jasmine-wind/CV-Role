# 项目主线说明

## 一句话主线

AI 简历优化与岗位匹配系统围绕“简历资产”和“用户粘贴的目标岗位 JD”组织简历优化流程，帮助用户从简历解析、简历诊断、目标岗位解析、匹配分析、岗位优化建议到局部改写和岗位优化报告形成可演示闭环。

## 项目背景

普通求职者往往会遇到两个问题：

- 简历内容写了很多，但不知道是否命中目标岗位要求。
- AI 可以生成建议，但如果缺少依据和确认环节，容易变成泛泛而谈，甚至产生不真实内容。

本项目从可运行 MVP 出发，先打通用户、简历、岗位和 AI 分析主链路，再逐步增强 AI 结果的结构化、可追溯和可展示能力。

## 用户痛点

- 不知道简历和岗位之间的真实差距。
- 简历解析结果混乱时，后续 AI 分析质量会受影响。
- AI 建议如果没有依据，用户很难判断能不能采用。
- 局部改写容易越界，可能写出用户没有真实经历过的技能、项目或量化指标。
- 功能很多时，如果没有统一报告，演示和使用都会显得分散。

## 系统解决方案

系统采用“简历 + 用户粘贴目标岗位 JD + AI 结果聚合”的方式组织主流程：

```text
简历上传与解析
  -> 简历诊断
  -> 目标岗位提交与解析（用户粘贴真实 JD）
  -> 匹配分析
  -> 岗位优化建议
  -> 局部改写
  -> 岗位优化报告
  -> AI 结果回看
```

关键设计原则：

- AI 结果必须尽量结构化，便于展示、回看和验证。
- AI 建议只作为修改参考，不直接替用户编造事实。
- 岗位优化报告只聚合已有结果，不为了补依据重新调用 AI。
- 目标岗位以用户粘贴 JD 为主，系统预置岗位库只作为参考，不依赖岗位爬取。
- 缺少依据时保留 warning，让用户知道哪些结果需要谨慎确认。

## 技术演进

### Phase 1：基础可运行 MVP

完成注册登录、简历上传、文本提取、基础解析、AI 简历分析、岗位匹配、优化建议和历史记录，打通可演示主流程。

### Phase 2：工程化增强

补充配置、错误处理、日志、测试、API 文档、工程结构和基础质量保障，让项目更稳定、更容易继续迭代。

### Phase 3：AI 能力深化

围绕简历诊断、目标岗位解析、匹配分析、岗位优化建议、局部改写、AI 结果回看、解析质量回归和岗位优化报告持续增强。

当前 Phase 3 的重点收口产物是岗位优化报告：把匹配结果、建议、改写、依据、warning 和下一步清单聚合到一个可展示区域。

## 后续规划

### Phase 4：架构与工程质量

计划继续增强架构边界、服务可维护性、可观测性、回归测试和关键链路稳定性。

### Phase 5：产品化与部署

计划整理上线配置、部署方案、演示材料、README 展示、用户体验和可交付版本说明。

## 当前边界

当前项目不做：

- 岗位爬取或外部岗位自动采集。
- 完整定制版简历自动生成。
- DOCX / PDF 一键导出。
- 自动写回用户原始简历文件。
- 微服务拆分。
- 多轮对话式简历顾问。
- 自动编造经历、技能、证书、奖项或量化指标。
