# Phase 1 Task List

## 0. 文件用途

本文件用于拆解 Phase 1 的具体开发任务。

`docs/phase-1-mvp.md` 负责说明 Phase 1 要做什么。  
本文件负责说明每个版本下面具体怎么拆小任务。

使用原则：

1. 每次只做一个小任务。
2. 每个小任务都要有目标、任务、验收标准。
3. 完成一个小任务后，更新 `docs/codex-context.md`。
4. 完成一个 v0.x 版本后，更新对应迭代日志。
5. 不允许跳过当前任务直接实现后续版本功能。

# v0.2 - 简历上传与文件存储


状态：当前版本

## v0.2 目标

完成简历上传闭环，保存简历文件和简历元数据。

v0.2 只负责文件上传、文件存储和元数据管理，不进行简历文本提取和结构化解析。文本提取与解析放到 v0.3。

v0.2 完成后应满足：

- 已登录用户可以上传 PDF、DOC、DOCX 简历。
- 未登录用户不能上传简历。
- 不支持的文件类型会被拒绝。
- 超过大小限制的文件会被拒绝。
- 上传成功后文件可以在存储服务中找到。
- 上传成功后数据库中有对应元数据。
- 用户只能查看自己的简历记录。
- 前端可以展示上传后的简历列表。
- 本轮结果记录到 `docs/iteration-log/v0.2-upload.md`。

## v0.2.3 文件上传接口

状态：未开始

目标：

- 实现 `POST /api/resumes`。
- 校验登录状态。
- 校验文件大小和文件类型。
- 调用文件存储服务保存文件。
- 保存简历元数据。

任务：

- [ ] 定义文件大小限制。
- [ ] 定义支持格式 PDF、DOC、DOCX。
- [ ] 校验文件后缀。
- [ ] 校验 Content-Type。
- [ ] 创建 `ResumeController`。
- [ ] 创建 `ResumeService`。
- [ ] 实现 `POST /api/resumes`。
- [ ] 从当前登录用户中获取 `user_id`。
- [ ] 调用 `FileStorageService` 保存文件。
- [ ] 保存上传用户、原始文件名、文件类型、文件大小、存储路径或对象 key。
- [ ] 返回上传结果。

失败处理策略：

- 文件保存失败时，不写入数据库元数据。
- 文件保存成功但数据库保存失败时，应记录错误，并尽量清理已保存文件。
- Phase 1 不做复杂文件内容安全扫描。

验收标准：

- 已登录用户可以上传简历。
- 未登录用户不能上传。
- 不支持格式被拒绝。
- 超过大小限制被拒绝。
- 上传成功后文件存在于存储服务中。
- 上传成功后数据库存在对应元数据。
- 暂不实现复杂文件去重。
- 暂不实现简历解析。
