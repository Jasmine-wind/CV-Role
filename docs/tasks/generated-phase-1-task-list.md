# Phase 1 Task List

## 0. 文件用途

本文件用于拆解 Phase 1 的具体开发任务。

`docs/phase-1-mvp.md` 负责说明 Phase 1 要做什么。  
本文件负责说明每个版本下面具体怎么拆小任务。

使用原则：

1. 每次只做一个小任务。
2. 每个小任务都要有目标、任务、验收标准。
3. 完成一个小任务后，更新 `docs/codex-context.md`。
4. 完成一个 v0.x 版本后，更新对应迭代日志。
5. 不允许跳过当前任务直接实现后续版本功能。

# v0.3 - 文本提取与结构化解析

状态：已完成

## v0.3 总结

v0.3 已完成简历文本提取与基础结构化解析闭环：

- 已设计 `resume_parse_results` 表，并创建 ResumeParseResult 实体和 ResumeParseResultMapper。
- 已通过 `resume_id` 关联 `resumes.id`，并限制一份简历只保留一条最新解析结果。
- 已集成 Apache PDFBox 和 Apache POI，支持 PDF、DOC、DOCX 简历文本提取。
- 已在文件存储服务中增加 `open(String objectKey)`，支持通过已上传简历的对象 key 重新读取文件。
- 已实现 `ResumeTextExtractionService`，处理不支持类型、空文本和文件读取失败等异常。
- 已实现 `ResumeStructureParseService`，基于规则提取姓名、手机号、邮箱、技能关键词、教育经历、项目经历和实习或工作经历。
- 已实现 `POST /api/resumes/{id}/parse` 解析触发接口。
- 已实现 `GET /api/resumes/{id}/parse-result` 解析结果查询接口。
- 已保证用户只能解析和查看自己的简历解析结果。
- 已实现重复解析覆盖旧结果，解析失败时保存 `FAILED` 状态和错误信息。
- 已实现前端 `/resumes` 页面中的“开始解析”和“查看结果”操作。
- 已展示解析状态、原始文本、基础结构化字段、技能关键词和经历列表。
- 已补齐简历删除闭环：`DELETE /api/resumes/{id}`、前端删除按钮、删除后刷新列表和清空当前解析面板。
- 已完成前后端联调，验证 PDF/DOCX 文本提取、解析结果保存和查询、重复解析覆盖、用户数据隔离和解析失败提示。
- 已运行后端 `./mvnw -DskipTests package`。
- 已运行前端 `npm run build`。
- 迭代日志已更新：`docs/iteration-log/v0.3-parse.md`。

说明：

- v0.3 不调用 AI，不做岗位匹配，不生成简历优化建议。
- 当前基础结构化解析以规则为主，字段划分会受简历模板影响。
- 后续 v0.4 AI 简历分析应优先使用准确的 `extracted_text`，`structured_json` 只作为辅助信息。
- 图片型简历、扫描型简历、复杂 OCR 不属于 v0.3 支持重点。
