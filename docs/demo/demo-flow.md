# 演示流程

## 演示目标

用一份虚构 Java 后端简历和一份虚构 Java 后端岗位，展示系统如何从简历上传走到岗位优化报告。

演示过程不使用真实手机号、真实邮箱、身份证号或真实公司敏感信息。

## 演示前准备

- 后端已启动：`http://localhost:8080`
- 前端已启动：`http://localhost:5173`
- PostgreSQL 已完成 Flyway 迁移。
- `.env` 中配置了可用的 OpenAI-compatible API Key。
- 准备虚构简历内容：`docs/demo/demo-resume-java-backend.md`
- 准备虚构岗位内容：`docs/demo/demo-job-java-backend.md`

## 演示步骤

### 1. 注册 / 登录

1. 打开前端首页。
2. 注册演示用户。
3. 登录系统，进入工作台。

演示要点：

- JWT 鉴权生效。
- 未登录用户不能访问受保护页面。

### 2. 上传简历

1. 进入“我的简历”。
2. 上传一份由虚构样例制作的 PDF、DOC 或 DOCX。
3. 查看简历列表中出现上传记录。

演示要点：

- 文件元数据保存。
- 支持 PDF、DOC、DOCX。

### 3. 解析简历

1. 在简历列表触发解析。
2. 查看提取文本、基础信息、教育经历、技能、项目经历等结构化结果。
3. 查看解析模式、质量提示和调试信息入口。

演示要点：

- 解析结果不是直接展示原始文本。
- 解析质量 warning 不等于解析失败。

### 4. AI 简历诊断

1. 对已解析简历触发 AI 简历分析。
2. 查看评分、优势、问题和建议摘要。

演示要点：

- AI 诊断只基于用户简历内容。
- 建议需要用户确认后使用。

### 5. 新增目标岗位

1. 进入“目标岗位”。
2. 粘贴 `docs/demo/demo-job-java-backend.md` 中的虚构岗位内容。
3. 保存岗位。

演示要点：

- 岗位数据由用户提交。
- 演示岗位不包含真实公司敏感信息。

### 6. 解析目标岗位

1. 触发目标岗位解析。
2. 查看岗位标题、技能要求、职责要求、经验要求等结构化信息。

演示要点：

- 目标岗位解析为后续匹配提供结构化输入。

### 7. 匹配分析

1. 进入“匹配与优化”。
2. 选择已解析简历和已解析目标岗位。
3. 点击“开始匹配分析”。
4. 查看匹配分数、强匹配项、弱匹配项、缺失技能、风险提示和依据。

演示要点：

- 匹配不是只看关键词，而是输出结构化差距。
- 风险提示用于避免虚构能力。

### 8. 岗位优化建议

1. 点击“生成岗位优化建议”。
2. 查看高 / 中 / 低优先级建议。
3. 展示建议依据和注意事项。

演示要点：

- 高优先级建议优先处理。
- 缺少依据时报告会显示 warning。

### 9. AI 局部改写

1. 选择一个真实项目经历片段。
2. 触发局部改写。
3. 查看原文、改写建议、改写理由和注意事项。
4. 演示采纳或拒绝状态。

演示要点：

- AI 只优化表达。
- 采用前必须确认没有新增虚假事实。

### 10. 岗位优化报告

1. 点击“查看优化报告”。
2. 查看报告概览、匹配结论、优化建议、局部改写建议、下一步清单和生成信息。
3. 查看 warning，说明哪些历史 AI 结果缺少依据。

演示要点：

- 报告聚合已有结果，不重新调用 AI。
- 报告不是 JSON dump，而是结构化展示。

### 11. AI 历史回看

1. 进入 AI 结果回看页面。
2. 查看简历诊断、匹配分析、岗位优化建议和局部改写结果。

演示要点：

- 用户可以回看历史 AI 结果。
- 适合解释系统的完整闭环。

## 演示收口话术

本项目目前完成的是本地可运行的 AI 简历优化闭环。系统不会直接替用户生成不可核查的完整简历，而是围绕目标岗位给出结构化匹配差距、可执行建议、局部表达优化和最终岗位优化报告。
